# Typed Decision Models: Fit f1 Diagnosis (methodology)

> **Status:** active · **Owner:** `data-scientist` · **Tracks:** — · **Extends:** `docs/plans/typed-decision-models-fit-ml.md`

Scope: the three U6fL f1 fits (guard-judge v1, message-type-classifier v2, join-in-judge v2), decision model `laya`, H = `qwen/qwen3-4b-2507`, 180 s decision timeout, no aborts, no exclusions, no parse failures (`k = 0` on every call kind), both models resident start and end. All figures below were recomputed from `decision-models/data/*/fits/*-f1.fit-report.json`, the calls files, `items.jsonl` and `splits.json`; the bars are `docs/plans/typed-decision-models-ml.md` §Q2.1/§Q2.2/§Q3/§Q5.

**Verdict: approve the fits as valid measurements; all six `fit-infeasible` outcomes are genuine, not method artifacts.** Recommended: close guard as a negative result; for message type and join-in, take no new H on speculation, and put a user decision on the table (§5).

## 2. Genuine, or artifact?

**Genuine, and located.** Two independent limits, neither an artifact of method, size, labels or balance.

1. **Laya is a weak discriminator on these tasks** (decision-only rows). Calibration AUC of the selected texts is 0.60-0.70 (guard 0.644; message type 0.60-0.71; join-in 0.60-0.70); the best of five texts per point is within the 0.5-1.0 range only modestly above chance, so the winner's-curse caveat (fit note §3) cuts the other way: the true figure is not better. The message-type confusion for `m-precedence` shows collapse toward `order` (other -> order 48/60, escalation -> complaint/order 52/60, complaint -> order 27/60). The guard cells with p ~ 1e-12 are decisive at n = 100: Laya's correct-rate there is 52/100 (turns/yes) and 45/100 (understanding/no) against H's 100/100 and 93/100.
2. **H is itself below the bar on a subpopulation, so no composite can clear it** (hand-off rows). With H answering every item (s = 1), calibration agreement is: message type question 46/60 = 0.767, order 0.95; join-in 0.84 (no) / 0.89 (yes). Laya adds nothing on those items: the hand-off composite's minimum equals H's own (0.767 on message type under all five texts, identical to three decimals; join-in 0.85-0.86). This is §Q2.2 rung 4's documented case ("the hand-off LLM itself agrees below 0.90 in some class"). The `m-control` vs `m-definitions` etc. selection is therefore a tie-break among equal minima, not evidence about the texts.

**Where H fails (message type).** 13 of the 14 H errors on `question` are the same pattern: a question carrying a past grievance clause ("last two times ... sold out", "the size M ... came out tighter"), which H labels `complaint`; a keyword heuristic of mine flags 16 of 60 calibration questions, so roughly 12 of 16 such items fail against about 2 of 44 others (heuristic, not a measured partition). H's own prompt says question = "not unhappy about anything", so H is following its prompt against a label that three blind Sonnet votes set. That is a boundary the data design deliberately probes, so it is a prompt/label-definition limit of the incumbent-style prompt, and partly label-boundary ambiguity (several of these are arguably dissatisfaction raised once, which the decision-only question text itself calls `complaint`). I cannot adjudicate which side is right from here; the bar is against the labels.

**Not the explanation.** Label noise: blind-label pair agreement is 97-99% (join-in 0.991/0.997; message type 0.97-1.0, question 0.970; guard 0.976/0.985; `diagnostics.json`), far below the 10-25 pp gaps. Class balance: balanced by construction (60 per class, 100 per cell). Size: the gaps are decisive except one, join-in hand-off: 84/100 (Wilson [0.756, 0.899]) and 89/100 ([0.814, 0.937]) do not statistically exclude a true 0.90 for the yes class, and with true agreement 0.86 the two-class conjunction passes at n = 100 with probability about 0.16 per class (§Q5.3 gives 0.10-0.33 for 0.85-0.88); so join-in hand-off is "below the bar, not certainly", and a pass at eval would be the exception. The method itself behaved per spec: the fallbacks fired as the notes rule, and the `ranking` outcome did not fire (all AUCs > 0.5).

**Other H or other decision model: speculation, with one weak prior.** No run in the repo measures any other H on these roles: `model-bench/results/index.csv` has no join-in or message-type rows at all (only embedder, guard-judge, chat-responder, nlq, tool-caller). The only comparative evidence is the guard-judge-understanding sweep over 17 small models, where `qwen/qwen3-4b-2507` is top or near-top (falseAdvance 4/40, advanceRecall 26/30); a 27B (`prism-ml/bonsai-27b`) and the thinking variant of the same model failed to advance at all (advanceRecall 0/30 and 1/30) with latencies of 12 s and 4.2 s. That says larger or reasoning-tuned is not reliably better with this prompt shape, and nothing about join-in or message type. For the guard, H is fixed regardless: it is the incumbent (FR-3 pairing, plan4 §3.11), and a faster-than-incumbent H would break the "no worse than the incumbent" comparison.

## 3. The guard latency failure is real

Hand-off latencies (n = 400, all ok): median 0.657 s, mean 0.673 s, max 1.27 s; Laya decision median 22 ms. Latency mean t_L = 672.6 ms, td = 20.3 ms. The FR-2 ceiling is `s_2 = (t_L/2 - td)/t_{L|H} = 0.469`; the smallest `s` that keeps `D_c <= 0` is 0.99 (all five texts: 0.99-1.0). So the quality target and the speed ceiling cannot both be met: the composite is slower than half the incumbent by a factor of two, and indeed 2.1x of ceiling. Noted: the fit's `g-completeness` has td = 110 ms because two decision calls took 15.7 s (the model's first-call or load stalls, 0.5% of calls; the half-budget count is 0); it moves that text's `s_2` to 0.336 only, no effect on the verdict. The `fit-infeasible: latency` label on the hand-off candidate is the named-first bar; its quality target is satisfied only trivially (handing off nearly all items, a degenerate composite that is the incumbent plus 20 ms).

## 4. Method observations (no defects found)

- Hand-off `D_c <= 0` is trivially met when `s ~ 1`; the ladder reports it faithfully. Do not read `agreementUnmet: false` on that candidate as a quality pass.
- The calibration set has never touched the eval split, so another fit series (`f2`) is clean with respect to eval; each additional H or text tried on calibration adds a selection effect at n = 60-100 per class, so cap at two H candidates and report both.
- Nothing here needs a code or statistics change in the fit.

## 5. Recommendation

1. **Guard: close as an honest negative result.** Laya cannot match the incumbent on four cells at any threshold (p down to 1e-15), and the incumbent is the only legal H. No more H or text trials. Rework of the decision-model side would be fine-tuning (note §Q7, train split exists), a separate decision, not a fit retry.
2. **Message type and join-in: do not run another H on speculation.** The hand-off ceiling is H's own agreement; a different H helps only if it scores >= about 0.92 per class alone, and there is no evidence either way. The cheapest evidence is H-alone screening through the existing `model-bench` packs `message-type-classifier-synthetic` and `join-in-judge-synthetic` on two or three models (the 4B comparison set already used for the guard): no new infrastructure, no touch of the decision-models eval split. If one clears roughly 0.92 per class there, run one `f2` fit with that H; else close.
3. **Bar and scope decisions belong to the user**, and I flag them as such rather than proposing a change: (a) whether FR-10's 0.90 per-class floor stands when H alone cannot meet it (the requirement was set against the decision model's job; with H below the bar the point has no passing composite); (b) whether the message-type `question` vs grievance-clause boundary should be re-labelled or kept as a deliberately hard class (a data-design call; relabeling after seeing outcomes would be a selection on the outcome and need a new dataset version); (c) whether the fine-tuning rung (§Q7) is wanted, which is the documented lever for the weak decision model.
4. **U6i imports: yes, for all six.** `_fit_problem` loads these outcome/target pairs by design, importing is cheap and reversible, and the plan (§Q2.0, FR-4) requires every `fit-infeasible` candidate to be evaluated once so "does not meet its bar" is a measured verdict. Run replicate 1 only where it fails the bar (§Q2.0 allows skipping replicate 2). If the user wants to save effort, a FR-4 waiver for the foregone decision-only candidates (guard 3-of-4 cells rejecting at p < 0.01; message type min 0.033; join-in 0.66) is a requirements decision for the user, not mine; my own view is that the single replicate costs little and keeps the record uniform. Do not ship the guard hand-off candidate: it is the incumbent plus overhead.
