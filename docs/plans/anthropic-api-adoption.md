## 1. Goal & scope

Make the Anthropic Messages API usable, opt-in, from the three modules that call an LLM through code: `falkor-chat` (per-workspace switch), `model-bench` (hosted arm, 4 roles + 3 decision points) and `decision-models` (API generation/labelling path). Defaults stay local (FR-1). Out of scope: embeddings, extraction, `tank`, `mcp-monitor`, spend caps, other providers, any change to a local default (requirements, Out of scope).

CPG: considered, not relevant — the change is a new wire adapter plus config, record fields and docs, located by reading `modelconfig.py`, `llm.py`, `transport.py`, `retry.py`, `runner.py`, `campaign.py`, `install.py`; no call-graph question needed.

## 2. Findings that shape the design

- **falkor-chat seam** (spec: SERVER §1.8). `FallbackClient` falls back on **every** `ProviderCallError` (`llm.py:FallbackClient.chat/complete`), so an invalid key would silently fall back; `retry.is_transient` switches on a closed `kind` set and reads `detail` (the provider's error text). Clients are built per call (`_build_llm`), so a key read at build time picks up rotation with no restart. `FallbackClient.complete()` returns `str`: the guard judge, the nested `query_graph_data` call and the responder carry no answering-model, fallback or usage out. `requested` (workflow `config.model`, `run["stepModel"]`, a guard's `model`) is a rung of `resolve()` that a workflow def, which is workspace data, controls. The override is read once per drive (`executor.py:683`) and stamped on the run. `write_model_overrides` is called only from `scripts/embedding_migration.py`: **no route or script switches a workspace today**, and it clears any `None`. `extraction` is outside `KINDS` (K-080). The storefront def pins `config.model`, but the override is a hard cap, so switching `demo` needs no def bump.
- **model-bench** talks to LM Studio's `/api/v0` only (`lmstudio.py`); `run_pack` is a ten-step LM Studio capture order. Profiles were added additively to schema 1 before (`fingerprint.py` docstring). A decision-point pack declares `lmstudio-chat` plus the additive `lmstudio-decisions`, so its derived surface is `chat` and `agreement.build_messages`/`answer_from_chat`/`score_item` already score a plain chat run; a hosted arm on a decision point is an ordinary chat run (FR-6). The drivers (`_drive_single_call_items`, `_drive_decision_items`, `_drive_handoff_items`, `_drive_conversations`) take `lmstudio` and `baseline_residency`. `rank_report` keeps one run per `modelKey` (`cli._select_rank_arms`) and raises `DuplicateModelInReport` otherwise.
- **decision-models** drives `claude -p --agent dm-driver` children over a file exchange (`runner.py`), audits child transcripts (`audit.py`) and pins each role's `model`/`effort` from the **agent definition frontmatter** at `install` (`install.py` `definition_error`, pins at ~264); `promptSha256` hashes the definitions. Those definitions (`agents/dm-generator.md`, `dm-labeler.md`) are tool-use scripts ("Read the request file… Write the answer file… reply `done`") that a tool-less API call cannot follow. Invariant "No hosted API client" (`decision-models/AGENTS.md`); `tests/test_fr8_isolation.py` allows stdlib + itself.
- **Anthropic facts** (docs fetch 2026-11-19; each unconfirmed one is a U1b probe item, §4): every current model id is a pinned snapshot; `claude-haiku-5-5`, `claude-sonnet-5-5`, `claude-opus-5-5`. Errors: 401 auth, 402 billing, 403 permission, 429 rate, 5xx/529 overload; body `{"type":"error","error":{"type","message"},"request_id"}`. Models from 4.7 up return 400 for `temperature` below 1; Opus 5.5 thinking is always on and counts toward `max_tokens`. The OpenAI-compat endpoint is documented as "primarily for testing … not production-ready" and cannot control effort or adaptive thinking.

## 3. Design

### 3.1 Wire: a native Messages adapter
Each module keeps its OpenAI-shaped internals; one stdlib module translates at the edge. **Canonical `model-bench/modelbench/anthropic_wire.py`**, byte-copied to `falkor-chat/server/falkorchat/anthropic_wire.py` and `decision-models/decisionmodels/anthropic_wire.py` (precedent: model-bench is the canonical source of copied contracts). Drift guard: each copy's own tests pin its **SHA-256** (no cross-component read), the existing skip-if-absent byte-equality test is the second line, and a planted one-byte drift must turn it red. The wire's security tests (§3.3) are duplicated identically in each component so a divergent copy fails locally. Pure functions plus one `post`, no logging, no module state:

- `build_request(payload) -> dict`: OpenAI chat payload → Messages body. `system` hoisted; assistant `tool_calls` → `tool_use`; consecutive `tool` messages → one user message of `tool_result` blocks; `tools[].function` → `{name, description, input_schema}`; `max_tokens` required (a conservative default when absent, F11); `temperature` never sent; overlay params `thinking` and `effort` map to `thinking` and `output_config.effort`.
- `parse_response(body) -> dict`: Messages response → OpenAI-shaped `{model, choices[0].message{content, tool_calls}, finish_reason, usage}`. `usage.prompt_tokens` = `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`; `completion_tokens` = `output_tokens` (thinking included); a bound counts both (ML note §3.4). Thinking blocks dropped. `finish_reason` carries the raw `stop_reason` so callers can tell `end_turn`, `max_tokens` and `refusal` apart.
- `post(base_url, body, *, key_file_env, timeout, opener=None) -> dict` raises only `AnthropicWireError(kind, status, error_type)`; `kind` ∈ `auth` (401, 403, missing/invalid key), `billing` (402, or a 400 whose message carries "credit balance"/"spend limit"), `rate` (429), `overloaded` (5xx, 529), `network` (connection, timeout, read), `request` (any other 4xx, a redirect, malformed body). **Every message is composed only from `kind`, `status` and an `error_type` mapped through an allowlist** (`authentication_error`, `permission_error`, `rate_limit_error`, `overloaded_error`, `billing_error`, `invalid_request_error`, `not_found_error`, `api_error`, else `unknown`); never `str(exc)`/`repr(exc)` of any stdlib exception, never the provider's body, headers, request id, org or workspace id (FR-10); raised `from None`. A final `scrub()` removes the key value and `sk-ant-[A-Za-z0-9_-]+`.
- `require_pinned(model_id)`: refuses an empty id or one ending `-latest`; the stored identifier is the response's `model`.

**Why native, not the OpenAI-compat endpoint.** Compat needs no translation code, but cannot set effort or adaptive thinking (Opus 5.5 would think at default effort on every item and consume `max_tokens`) and is not positioned for production. Cost: ~150 lines plus tests in three guarded copies.

### 3.2 Models
**Small `claude-haiku-5-5`, large `claude-opus-5-5`** for falkor-chat roles and bench arms. Their settings (thinking, effort, `max_tokens` allowance), the truncation rule and the token-bound sizing have **one home: ML note §3.1 and §3.4**; the overlay and the bench read the same per-model values from it. `claude-sonnet-5-5` is the decision-models labeller and never a scored arm (§3.6).

### 3.3 Key handling (FR-11; `security-expert` gate before U1a merges)
- **Storage:** a file outside the repository, one line, provisioned by the operator in a human terminal (`umask 077; read -rs` redirected to the file), never `echo`ed in an agent session or typed into history. Docs and context files refer to it as `$ANTHROPIC_API_KEY_FILE` and publish no path. **No key in any environment variable.**
- **Opt-in per process:** read only when `ANTHROPIC_API_KEY_FILE` names it, set for the holder processes (the chosen falkor-chat server, `model-bench run --hosted`, `driver api-run`, the human-run live scripts). Unset → `auth` "no key configured" (FR-1/AC-1). `tank`, `mcp-monitor`, the `:8200` server and the `claude` children of `driver run` never get it. This prevents accidents only: an agent can set the variable itself and run a holder command, and `--token-bound` limits spend, not access.
- **Loader (refuses with a closed message that never includes content):** `os.open(..., O_NOFOLLOW)`, then `fstat` on the descriptor: regular file, `st_uid == geteuid()`, `mode & 0o077 == 0`; parent directory not group/other-writable; resolved path not inside a directory tree containing `.git`; content, after stripping one trailing newline, matches `^sk-ant-[A-Za-z0-9_-]{20,}$` (so CR/LF and non-latin-1 never reach a header). A key under `/mnt/c` (drvfs reports 0777) is always refused; the operator note says so. Read per call, never cached; rotation is a file edit.
- **Endpoint rule (one rule, in the shared `post`, evaluated before the key file is opened):** `urllib.parse.urlsplit`; scheme `https`, hostname exactly `api.anthropic.com`, no userinfo, query or fragment, port empty or 443; **or** `http`/`https` with a literal loopback IP (`127.0.0.1`, `::1`; the `localhost` name is refused). `post` uses a dedicated opener: `ProxyHandler({})`, a redirect handler that turns any 3xx into `request`, default certificate verification. Tests: `api.anthropic.com.evil.test` and `api.anthropic.com@evil.test` refused; a stub that 302s to a second loopback listener, which must see no key; `http_proxy` set with a loopback stub, the proxy must see nothing; no unverified TLS context is ever created.
- **Provider config carries no key.** For `protocol == "anthropic"` the loader refuses any `apiKey`, `headers`, `{env:}` or `{file:}`, and refuses an anthropic-protocol provider declared in the shared `opencode.json` (only the falkor-chat overlay may declare it); `_auth_headers` is not used on the hosted path.
- **Never in:** config, results, ledgers, graph records, argv, prompts, fixtures (fixtures use `sk-ant-FAKE-CANARY-…`), logs (the base URL is logged, and the endpoint rule keeps it free of userinfo/query).
- **Residual risk, stated plainly:** every Claude Code session here has bare `Bash` and `Edit(**)` allowed (`.claude/settings.json`) and runs as the same user, and `tank` and the decision-models `claude` children can read files, so an LLM-driven agent can read a `0600` file, and a permitted `curl` could send it anywhere. A project-level `permissions.deny` is **not** a control (the same file is editable under `Edit(**)`; `Bash` deny rules match command text and miss `cat ~/.config/graph*/anth*`, `python -c`, `find … -exec cat`); the decision-models children run with an arbitrary cwd, so project settings do not even reach them. What the plan does: user-scope `~/.claude/settings.json` `Read` deny on the key directory, documented as a **tripwire, not a barrier**, plus one human-run live check in U1b that a `Read` of the file and a plain `cat` are refused and that `python -c`/glob forms are not. A hard control exists only as a separate low-privilege OS user owning the file behind a loopback broker that adds `x-api-key` (the holders never read the key; the endpoint rule moves into the broker) or an OS-enforced Claude Code sandbox `filesystem.denyRead` on the key directory (setting name and scope to be verified in the docs before adoption). Neither is built (stakeholder decision: not in this feature; see R3).

### 3.4 falkor-chat
1. **Provider.** `SUPPORTED_PROTOCOLS` gains `anthropic`; `ProviderSpec`/`ResolvedModel` gain `hosted` (true iff protocol `anthropic`). The provider is declared in the shipped overlay `falkor-chat/config/models.json`, not the shared `opencode.json`: `"providers": {"anthropic": {"protocol": "anthropic", "baseURL": "https://api.anthropic.com"}}` (the override branch of `_build_provider_spec` accepts an overlay-only provider). The refusal text at `modelconfig.py:~537` and SERVER §1.8's protocol statement are rewritten (the K-043 pointer is dropped). `_build_llm` builds, for a hosted spec, an `OpenAICompatibleLLM` over a new `anthropic_transport` (`transport.py`) wrapping `anthropic_wire`.
2. **Error mapping, no new kinds, no `detail` (retry/fallback).** The transport raises `ProviderCallError` reusing the existing closed kinds: HTTP-derived wire errors as `kind="http"` with the real `status` (so `retry.is_transient` keeps working unchanged: 429 and 5xx are transient, 402/401/403/400 are not, `fallback_exhausted` over such causes is judged correctly) and connection-level ones as `connection`/`network`/`timeout`/`read`; **`detail` is always `None`** for hosted errors, and `str(exc)` is the closed wire message. New `ProviderCallError.fatal: bool = False`, set from wire `auth` and `request`. `FallbackClient.chat/complete` re-raise immediately on `exc.fatal`; `billing`, `rate`, `overloaded`, `network` fall back (FR-3). Local providers never set `fatal`, so FR-1 behaviour is unchanged. `request` is fatal so a 400 from an unsupported parameter is not hidden behind silent local answers. The fatal message names model, status and mapped error type, and the fix ("key file missing, unreadable or revoked").
3. **Roles (FR-3).** Overlay roles: `claude-small` = [`anthropic/claude-haiku-5-5`, `lmstudio/qwen/qwen3-4b-2507`], `claude-large` = [`anthropic/claude-opus-5-5`, qwen], `claude-small-demo` = [haiku, `lmstudio/mistralai/ministral-3-3b`]. Per-model overlay settings carry the ML note §3.1 values and a conservative default `maxTokens` per hosted call (a cheap guard that does not contradict FR-14).
4. **Hosted only via the workspace override (F3, FR-2, FR-4).** In `ModelGateway.resolve()` a chain containing a hosted element is allowed **only when `source == "workspace"`** and the kind is `agent`, `step` or `guard`; for `requested` or `default` sources, for `embedding`, `extraction`, and in publish-time validation (`_check_models_resolvable`, no `ws`), it raises `ModelResolutionError`. A workflow def therefore cannot name a hosted model; switching is the single observable act. A later explicit per-workspace opt-in is a separate flag if ever wanted.
5. **Private flag (FR-15, AC-10).** `WorkspaceConfig.private` (boolean; absent = not private, the stakeholder's decision). For every **hosted** resolution the gateway reads `private` fresh from the graph through a new `WorkspaceOverrides.is_private(ws)` port method (one RO query, hosted calls only; the per-drive override snapshot is not used for it, so a flag set mid-drive stops the next call). Fail closed on the hosted path: a read error, a missing or ill-typed value, or `ws is None` for a hosted chain is treated as private and refused. Local-only chains never read it.
6. **Records (FR-10).** `ChatResult` gains `usage: tuple[int, int] | None` and `hosted: bool | None` (from the client's constructor); `FallbackClient`'s `replace(...)` preserves them. The executor writes on each `StepRun`: `modelHosted` (true when the step's resolved chain has a hosted primary: a property of the switch, independent of which calls happened to return a `ChatResult`; `modelFallback` shows when local answered), `modelTokensIn`, `modelTokensOut` (summed over the agent loop's `chat()` calls); `resolvedModel` stays the last iteration's. `record_step_and_advance` writes them and the step-runs read projects them. **Counted: agent-loop `chat()` calls only.** The guard judge, the nested `query_graph_data` call and the responder use `complete()`, which returns `str` (so neither their answering model, a fallback, nor tokens are recorded): a step's tokens are a floor, stated in SERVER §1.8.  (Requirements decision log, 2026-11-19: a stated floor satisfies FR-10.)
7. **Operator surface.** `falkor-chat/scripts/workspace_models.py` (+ `.sh` wrapper with the preflight of `pin_workspace_embedding_model.sh`): `show <ws>`, `switch <ws> --role claude-small|claude-large|claude-small-demo [--kinds agent,step,guard]` (default all three; read-modify-write so the embedding pin and other kinds survive), `revert <ws>`, `private <ws> on|off`. `switch` refuses a private workspace (AC-10), `embedding`, and any non-claude role. `demo` is switched with `--role claude-small-demo`.
8. **Accepted residual:** with `demo` switched and `/shop` public, any participant can spend credits (FR-14 leaves interactive use unbounded by decision); only the default `maxTokens` and the storefront's existing turn limits bound it. The operator note says customer free text goes to Anthropic in that mode.

### 3.5 model-bench
1. **Arm.** `RunConfig` gains `hostedModel`; exactly one of `modelKey`, `candidateId`, `hostedModel`. CLI: `run --pack <id> --hosted anthropic/<model> [--replicate N] --token-bound N` (`--token-bound` required for hosted runs, exit 4 otherwise). Allowed: packs with derived surface `chat` (the four role packs, the three decision-point packs); `embedder` refused (exit 4). **Synthetic-content check (FR-15):** a hosted run refuses a pack not listed, by `packId` + `packContentHash`, in a tracked `model-bench/hosted-allowed-packs.json` carrying the owner's `inputs: synthetic` attestation (the pack files stay untouched, so no content hash changes). Two packs derive from falkor-chat goldens and are confirmed synthetic by the stakeholder and carry the owner's attestation in this file.
2. **Client.** `modelbench/hosted.py: HostedChat.chat(...) -> lmstudio.ChatResult` (same dataclass; `stats`/`model_info`/`runtime` `None`; `usage` mapped; `toolCallForm` from `tool_calls`) over `anthropic_wire.post`; 429/529/5xx retried at most twice honoring `retry-after` (cap 30 s), other wire errors map onto the existing call-failed taxonomy. Stored id is the response `model`.
3. **Runner.** `run_pack_hosted` beside `run_pack`: host info (OS/versions only), item drive, assemble; no probe, residency, catalog, warm-up or attestation. The drivers take `lmstudio` and `baseline_residency`; pass a hosted-neutral residency hook (`None` = no load withholding) rather than forking them (read `_drive_single_call_items`, `_drive_conversations` and `_turn_timings` first; the riskiest step). The `max_tokens` override and the stored `truncated` outcome (ML note §3.1) are runner-level. **Token bound:** a running total of the four usage fields; the run stops **before the next call** once `used >= bound` (overshoot at most one call), exit 6, no run record. The aborted attempt is appended to a tracked `model-bench/results/aborted.jsonl` (`packId`, model, replicate, bound, used, time) so a re-run with a larger bound is never an unrecorded selection.
4. **Replicates (ML note §3.2).** Each hosted (arm, pack) is run twice: a `replicate` field (1, 2) in the fingerprint, run id suffix `-r<n>`, and a hosted report arm key `modelKey#r<n>`, so `_select_rank_arms` keeps both and `DuplicateModelInReport` does not fire; replicates are never pooled; the analysis unit stays the item. 14 arm-packs × 2 = 28 runs.
5. **Fingerprint.** Additive `armProfile` `hosted:chat` (schema 1): required `provider`, `hosted: true`, `modelKey` (pinned id), `replicate`, `anthropicVersion`, `thinking`, `effort`, `maxTokens`, `temperatureNote: "provider-default"`, `tokenBound`, `tokensIn`, `tokensOut`, `truncatedCount`, pack identity, bench/python/host OS, `startedAt`/`endedAt`; **forbidden:** every LM Studio field. Per `model-bench/REVIEW.md`, canonical vectors with expected values written independently of the profile table: one valid hosted record and one local-looking forgery per forbidden field. No org, workspace, header or request-id field exists.
6. **Report.** Hosted rows carry `[hosted]` and a footnote: not locally reproducible; sampling at provider defaults; **no latency claim** (no latency headline or floor is printed for hosted rows; per-call time is descriptive only); on the three decision packs, the ML note §3.3 caveat ("generator = this arm; labels from a same-family model" on Opus rows) and per-stratum printing (`guard-judge-synthetic` eval vs side-check). No hosted row enters a determinism claim or is an incumbent or candidate. The guard-judge role pack and the guard decision-point pack remain separate runs (AC-4). `results/transcripts/` is already ignored; root `.gitignore` gains `*.key`, `*.key.*`, `.env.*`.

### 3.6 decision-models
The API path has its **own definitions, own pins, its own install and its own surface**; the subagent definitions, `install`, pins and `driver run` are untouched.
1. **Definitions.** `agents/api/dm-generator-api.md` and `dm-labeler-api.md`: plain system prompts (no tools, no file steps) holding the same rubric/generator instructions the points supply, instructing the model to reply with the answer body only. Frontmatter keys: `name` (`dm-<role>-api`), `description`, `model`, `effort`, `maxTokens` (the model/effort/maxTokens values are **data in these files**, set to the ML note §3.3 values only after U1b; offline U8 work and tests use fixture definitions with placeholder values and never hard-code a model id or `maxTokens`). `apirun.py` puts the request text inline as the user turn, takes the response text as the answer body and writes the answer part in the existing exchange format to the path the request header names. A different prompt is a different provenance.
2. **Install, surface and refusals.**
   - **Install.** A **separate `driver install-api`** (a new function beside `install.install`, which is not modified; `--surface` is not added to it) validates the API definitions with a new `api_definition_error` (the API key set above; none of `tools`/`maxTurns`/`permissionMode`; `name`, positive-integer `maxTokens`, non-empty `model`/`effort`), copies nothing into `exchange/.claude` (there is no child; an existing `exchange/.claude/agents` refuses), and records one `expectations` event with `surface: "api"`, `roles` for `generator` and `labeler` only (pins `model`/`effort`/`maxTokens` read from the API definitions), `promptSha256 {apiDefinition: {role: sha}, requestTemplate, rubric}` and no spawn template, driver or guard hash. An `expectations` event without `surface` means `subagent` (today's installs, unchanged).
   - **Refusals** (one surface per campaign root for its life; each tested, each names the other command and says to start a new root): `install` on an API root, `install-api` on a subagent root, `driver run` on an API root, `api-run` on a subagent root. `api-run` refuses a model other than the recorded **API** pin, never comparing against an old install's `claude-opus-4-8`.
   - **`campaign.py` on an API root.** `Campaign._expected` reads `agentType`, `spawnTemplate` and `guardCommand`, which an API `expectations` event lacks; the issue and serve path (`next`/`issue`) must not call the subagent audit's `Expected` for an API root (the API path builds no `audit.Expected`; `audit_api_call` takes the recorded pin). `generator_template_hash` hashes only `agentDefinition`/`spawnTemplate`/`requestTemplate`: on an API root it also takes `apiDefinition`, so editing an API definition mid-campaign raises the generator-template halt exactly as a subagent definition edit does today.
   - **`finalize.py`** is surface-aware: `_prompt_hashes` requires `agentDefinition`/`spawnTemplate` for `generator`/`labeler`/`driver` on a subagent root and `apiDefinition` for `generator`/`labeler` on an API root; `generation.json`'s `model` comes from the ingested run record, which for an API run is the **answered model** the `api-call` event carries (no transcript); `SURFACE` and the per-role `tier` follow the recorded install (`claude-code-subagent` or `anthropic-api`; the tier is the family token of the recorded model id, so any model family is representable); one model per role as today.
   - **Data.** A point never mixes surfaces or generators; API-produced data is a **new dataset and pack version** (`labels.*.surface: anthropic-api`), stored v1/v2 data is neither regenerated nor mixed in, and local arms are re-run on a new pack version before any comparison (ML note §3.3).
3. **Models and settings** (single home: ML note §3.3): labeller `claude-sonnet-5-5`, generator `claude-opus-5-5` (requirements decision log, 2026-11-19), which is also the large scored arm; efforts, `maxTokens`, votes and sample sizes are the note's. The self-scoring bias is bounded and reported as ML note §3.3 states (caveat footnote and per-stratum rows on every decision pack, §3.5.6); it is not restated here.
4. **Path.** `driver api-run --token-bound N` (required, per invocation, FR-14) beside `driver run` (the no-key path, FR-7): one `Campaign`, `next()`, `issue()`, `anthropic_wire.post`, `Campaign.ingest`. No `claude` child; the child allowlist is untouched.
5. **Audit: a three-way stop-reason map.** `audit.audit_api_call(response, pin)`: `end_turn` → clean, then `ingest`'s existing closed schema/answer checks gate as today; `max_tokens` → **halt** (a sizing fault: recorded, `resolve` raises the cap, never counted toward the 3-attempt drop); `refusal` → class `safeguardStop`, the existing environmental HALT for the stakeholder, never counted; a response `model` other than the pin → refusal. `combine` precedence is unchanged. The implementer reads `audit.py`/`ingest.py` to fix class names.
6. **Ledger (FR-10).** `api-call {batch, model, tokensIn, tokensOut, thinking, effort, stopClass, hosted: true}` and nothing else (no headers, request id, body); `token-bound {runId, bound}` at start, `token-bound-stop {used, bound}` when the next call would start with `used >= bound` (then exit 0, an in-flight batch is never abandoned mid-ingest). Bound sizing: ML note §3.4. Any text `apirun.py` writes to `store/refusal` or a ledger reason comes only from the closed wire messages. `api-run` refuses a `--root` inside the git work tree.
7. **Invariants rewritten in `decision-models/AGENTS.md` at close:** "No hosted API client" becomes "the only hosted client is `anthropic_wire`, reached only by `apirun.py`; no key in `CHILD_ENV_ALLOWLIST`". `test_fr8_isolation.py` allowlist unchanged (stdlib + itself), with the `ANTHROPIC_API_KEY_FILE` literal allowed only in `apirun.py`/`anthropic_wire.py`; never widened to make a unit green.

## 4. Implementation steps (each leaves the tree green; TDD per unit)

## 5. Test strategy

Altitudes: unit (translation, classification, scrub, loader, fingerprint profile, token accounting), contract (guarded copies; hosted-record vectors), integration against a **local loopback stub Anthropic endpoint** (accepts a canary; scripted 200, 401, 402, 429, 529, 302, truncation and `refusal` replies) for AC-2/3/4/5/6/9/12 and the AC-7 success path; live (human, token-bounded): U1b, U5, U7, U9.

Ordered behaviors to drive red-green: (1) no env var → no socket opened, modules unchanged (AC-1); (2) `build_request` round-trips a tool conversation, `temperature` never emitted, usage sums four fields; (3) classification table; messages hold no body text, key or stdlib exception text; (4) loader refusals; key variants; (5) endpoint rule, redirect and proxy tests; (6) `FallbackClient` re-raises on `fatal`, falls back otherwise, local-only chains unchanged (AC-3, AC-12); `is_transient` over hosted errors; (7) hosted refused outside the workspace-override rung and for `embedding`/`extraction`; AC-11 positive; (8) private: refusal at switch, refusal on a later flag, read failure, missing key, `ws=None` (AC-10); (9) step record shows model, hosted, tokens, fallback; (10) bench: arm exclusivity, embedder and unlisted pack refused, no `--token-bound` refused, bound stop and abort ledger line, two replicates ranked, truncation, fingerprint vectors; (11) API campaign: reaches `ingest`, pins and surface refusals, three-way stop map, bound stop event; (12) canary plant/find/clean sweep. Edge cases: key rotated between two calls; revoked key mid-run; 400 credit message vs other 400; `-latest` id; response `model` differing from the request; cached-prefix usage; Opus tool-caller run skipped when R1 holds.

## 6. Risks & open questions

- **R1 — thinking-block round-trip.** If Opus 5.5's tool loop needs thinking blocks passed back (U1-3), the OpenAI-shaped message list cannot carry them: the Opus `tool-caller` bench run is **not run** and the gap printed (never a silently degraded arm), the storefront stays on `claude-small*`, and `claude-large` is limited to non-tool steps until a follow-up carries raw content blocks. AC-8 is unaffected (Haiku).
- **R2 — credit-exhaustion signature** (402 `billing_error` vs an older 400 message). The classifier handles both; U1b records the real one. A wrong guess either falls back on a permanent error (visible in `modelFallback`) or fails a transient one loudly.
- **R3 — key reachable by agents** (§3.3). No hard control is built (requirements decision log, 2026-11-19, key hard control). **FR-11 therefore holds up to the stated residual risk**: AC-7 tests the listed locations, not whether an agent can reach the file.
- **R4 — model-bench live spec owed** (ledger L6) before this feature's close.
- **R5 — token counts are a floor** in falkor-chat (§3.4.6; requirements decision log, 2026-11-19, step tokens); bench and campaigns count every call. A hosted-primary step that fell back shows `modelHosted` and `modelFallback` both true; SERVER §1.8 says so at close.
- **R6 — perishable facts.** Model ids, prices and retirement dates are from the 2026-11-19 fetch; re-check before U7/U9. A retired id fails loudly as `request`; re-pinning is an overlay/definition edit.
- **R7 — self-scoring and family bias** on the decision packs: the Opus arm is scored on its own writing; bounded to gross effects by the guard side-check and the optional human samples, not removed (ML note §3.3).
