## 1. Goal & scope

Build `llm-gateway/`, a new top-level, stdlib-only component: a library core, a key-holding process and an optional service, so any component gets provider choice, fallback, loading, call records and token ceilings by configuration. First adopter: ccg's interpreter and summarizer, brokered. Providers (FR-15): LM Studio, Ollama, Anthropic, generic OpenAI-compatible.

Out of scope: embeddings (refused, AC-23), follow-on migrations, usage/stats tooling, UI.

**What the guarantees are.** Threat model: an LLM-driven agent under the human's uid (not root; `sudo` needs a password; no Yama). Hard controls: the key in the holder's account (FR-8); the holder's validation and ceilings (FR-10); root-owned configuration, manifest and code (FR-3). **Stated limitation, not enforced (D-1, FR-8):** the broker/service→holder credential is a file in the human's account. A hostile same-uid process that reads it can call the holder as `broker` or `service`, skipping R5/R6 and every scope check, leave no broker audit record (`calls.log` has one), and spend up to the window ceiling; it cannot read the key, use an unpinned model, a non-https or internal endpoint or an off-list body key, or exceed the per-call ceiling. The user unit and credential are agent-writable (the code root protects code, not the unit's command). The broker's audit directory is human-uid writable (egress spec3), so AC-21's evidence is not tamper-proof.

## 3. Design & rationale

### 3.1 Code home and consumption (FR-11, FR-15, FR-20)
New top-level `llm-gateway/` (package `llmgateway`, Python 3.12, zero runtime dependencies, `tomllib`), not in `cpg/` (generic, like `cypher-mcp/`) nor falkor-chat. Three routes, one engine: the in-process library `Gateway` (local providers only; ccg adds a broker transport); the service (`llmgateway.service`, Unix socket); the single-file stdlib client `client.py`, byte-copied by follow-on components (a test pins its imports and bytes). ccg takes the library through `cpg/pyproject.toml` extra `gateway` (an editable path install of `../llm-gateway`), and a test asserts `ccg.broker` never imports `llmgateway`. `model-bench` and `decision-models` cannot import outside their folders (`decision-models/AGENTS.md` FR-8): they reach it only through the service and client (follow-on).

### 3.2 Engine, providers, transports
`Gateway.call(Request) -> Response`: resolve call site and chain (§3.5) → policy (§3.6) → library bound (§3.9) → per chain step: residency (§3.8) → `build` → transport `exchange` → `parse`/`classify` → one attempt record → retry/fallback (§3.3). `Request`: `call_site, scopes, run_id?, messages, tools?, settings, response_format?, options{retry, fallback}, load_mode?`; **no model or provider field**. `embed` raises `EmbeddingsNotAvailable`.

A provider (`kind` string; `providers/__init__.py` ships in D4 as a lazy registry mapping each kind to its module path and importing on first use, so the D5 module files need no edit to it) supplies `build, parse, classify`, optional `residency`, optional `ops` (FR-17). Transports: `DirectTransport` (connects only to loopback IP-literal origins from the effective allow-list, §3.5), `HolderTransport` (service → holder), `ServiceTransport` (inside `client.py`), ccg's `BrokerTransport` (`cpg/ccg/gateway/`).

Settings (FR-4, FR-18): neutral names `temperature, top_p, top_k, min_p, repeat_penalty, frequency_penalty, presence_penalty, max_tokens, seed, stop`, plus `response_format`/`tools` pass-through (no grammar field exists: a `grammar` request field is refused naming it, the OpenAI-compatible kinds pass any `response_format` unchanged, Ollama and Anthropic refuse a type other than `json_schema` naming it). Each provider table maps a neutral name to a wire field or `None`; `settings` (overlaid by `provider_settings.<provider id>`, then by the request's own, per name) are `required` unless named in `optional_settings`; an unsupported required one fails before any send, naming it; nothing is added.

| Provider | Wire | Mapping notes |
|---|---|---|
| `lmstudio` | `/v1/chat/completions`, `/api/v0/models`, `/api/v1/models[/load]`, `/v1/decisions` | settings 1:1; `stats`/`runtime` verbatim in `Response.provider_detail` (AC-20) |
| `ollama` | `/api/chat`, `/api/ps`, `/api/tags`, `/api/show` | settings under `options`; `max_tokens`→`num_predict`; `response_format.json_schema.schema`→`format`; `think` optional; load `context_length`→`num_ctx`; `keep_alive` only when configured |
| `openai_compat` | `/v1/chat/completions` | as `lmstudio` without residency or catalog |
| `anthropic` | `/v1/messages` | `max_tokens` required; `seed` and the penalties unsupported; `response_format`→`output_config.format`; reply `model` is the recorded identity |

Hosted Ollama is chat-only: `response_format` fails `rejected`, load settings are refused; `parallel` fails.

### 3.3 Failure classification, retry, fallback (FR-7, FR-19)
Temporary: `rate_limit, out_of_credit, outage, timeout, connection, model_not_loaded`. Permanent: `auth, permission, rejected, policy_refused, run_bound, config`. `classify` returns only the class (the error body is dropped there).

| Condition | Class |
|---|---|
| connection refused/reset, holder socket unreachable, broker `upstream-error`, broker `response-too-large` | `connection` |
| socket timeout, broker `timeout`, 504 | `timeout` |
| 5xx, 502, 529, Ollama queue-full 503 | `outage` |
| 429 | `rate_limit` |
| 402 / `billing_error`; a 400 matching the provider's owner `out_of_credit_patterns` | `out_of_credit` |
| LM Studio no-model-loaded error; strict-mode miss | `model_not_loaded` |
| 401 / 403 | `auth` / `permission` |
| other 4xx incl. Ollama 404, 413, context overflow, hosted-Ollama `response_format` | `rejected` |
| broker denial; service refusal; `BrokerUnavailable` | `policy_refused`; `policy_refused`; `config` |
| **holder refusal** (completed exchange, below) | per the code table |

**Holder refusals** are a completed HTTP exchange: status `499`, `Content-Type: application/vnd.llmgateway.refusal+json`, body `{"holderRefusal": "<code>"}`; the broker passes a `completed` body through, so it never becomes `upstream-error`. Every `classify` checks that content type first. Codes:

| Code | Cause | Class |
|---|---|---|
| `bad_credential`, `stale_timestamp`, `replayed_nonce`, `unknown_caller` | authentication | `config` |
| `endpoint_unknown`, `path_not_allowed`, `https_required`, `address_forbidden` | provider/transport validation | `policy_refused` |
| `model_not_pinned`, `limit_missing`, `limit_over_ceiling`, `body_invalid` (duplicate/nested key, both limit aliases, non-JSON) | request validation | `rejected` |
| `run_id_missing`, `run_unmatched`, `run_bound_reached`, `window_ceiling_reached`, `release_cap_reached` | FR-10 | `run_bound` |
| `key_missing` | no key file | `config` |

None is retried or falls back; the call fails naming the code. Only an unreachable holder socket is `connection`.

Retry and fallback happen only where the call site lists them (fallback = more than one chain step and a temporary class); `Request.options.retry/fallback = False` returns the first failure unmasked (AC-12). ccg's call sites set `retry = {max = 1, on = ["connection", "timeout", "outage"]}` (`ModelRun._send`'s rule) (AC-22).

### 3.4 The key holder, hosted path, FR-10 ceilings (FR-8, FR-9, FR-10, FR-11, FR-12)
**Deployment.** The holder runs under a dedicated OS account (`llmholder`), the only supported recipe here. Holder, installer and service code run **only from the root-owned code root** `/opt/llmgateway/` (`/usr/bin/python3 -I`), never the checkout or an editable install. The human runs `install.sh` subcommands with `sudo`. **Bootstrap (trust on first use; no git, ccg or repo Python as root):** the human, unprivileged, first runs `git clone --no-local --bare <repo> <scratch>.git` and pipes the reviewed tree from it into root's `tar`: `GIT_CONFIG_NOSYSTEM=1 GIT_CONFIG_GLOBAL=/dev/null git -C <scratch>.git archive <reviewed-sha> llm-gateway | sudo tar -x --no-same-owner --strip-components=1 -C /opt/llmgateway.new`, reads the extracted `deploy/install.sh`, checks `find /opt/llmgateway.new ! -type f ! -type d` prints nothing (tracked symlinks survive extraction), then `sudo` moves it into place. The archive holds tracked content only, with no check-copy gap. Later `install.sh` subcommands run from `/opt/llmgateway/deploy/`. The `service` caller is a `systemd --user` unit under the human's uid . `keyholder check-deployment` stats every artifact below, refusing a code path or ancestor writable by a non-root uid and any entry that is not (by `lstat`) a regular file or directory (injected stat provider; real in tier 2):

| Artifact | Created by (uid) | Owner:mode | Readers |
|---|---|---|---|
| `/opt/llmgateway/` (`src/llmgateway/`, `bin/keyholder.py`, `deploy/install.sh`) | the bootstrap pipeline (root `tar`) | root:root 0755, no writable ancestor | all |
| `/etc/systemd/system/llmholder.service` (`User=llmholder`, `RuntimeDirectory=llmholder`, mode 0711, `ExecStart=/usr/bin/python3 -I /opt/llmgateway/bin/keyholder.py`; `NoNewPrivileges=yes`, `ProtectSystem=strict`, `ReadWritePaths=/var/lib/llmholder`, `PrivateTmp=yes`, `LimitCORE=0`, `ProtectProc=invisible`, `RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6`, `CapabilityBoundingSet=`) | `install.sh holder-account` (root) | root:root 0644 | all |
| `~/.config/systemd/user/llmgateway.service` (service unit, same code root) | `install.sh caller service` (caller-uid child) | caller-uid 0644 | caller |
| `/etc/llmgateway/`, `/etc/llmgateway/ccg/` | `install.sh owner-files` (root) | root:root 0755 | all |
| `/etc/llmgateway/gateway.toml`, `/etc/llmgateway/ccg/system.yaml` (byte copy of the tracked manifest; human-confirmed diff) | `install.sh owner-files` (root) | root:root 0644 | all |
| `/var/lib/llmholder/` | `install.sh holder-account` (root) | llmholder:llmholder 0700 | holder |
| `/var/lib/llmholder/keys/<provider>.key` | `install.sh holder-account --key-from-stdin` (root, then chown) | llmholder:llmholder 0600 | holder |
| `/var/lib/llmholder/registry/<caller>.secret` | `install.sh caller` (root) | llmholder:llmholder 0600 | holder |
| `/var/lib/llmholder/{ledger.sqlite3,-wal,-shm}`, `calls.log` | holder (llmholder) | llmholder:llmholder 0600 | holder |
| `/run/llmholder/` (tmpfs: recreated at every holder start) | systemd `RuntimeDirectory` | llmholder:llmholder 0711 | traverse only |
| `/run/llmholder/holder.sock` | holder (llmholder) | llmholder:llmholder 0666 (the MAC authenticates) | all |
| `<caller home>/.config/llmgateway/callers/<name>.cred` | `install.sh caller <name> <caller-uid> <path>` (a child that has dropped to the caller uid) | caller-uid:caller-gid 0600 | caller |
| `state_dir` (records DB, WAL) | the library (caller uid) | caller-uid 0700 / 0600 | caller |

`install.sh caller` runs `keyholder add-caller <name> --caller-uid N --out PATH` (under the caller's home) as root: it writes the registry secret (32 random bytes, `llmholder`-owned), then forks a child that clears supplementary groups, drops to the caller uid (secret over a pipe, never argv) and creates the credential file by walking PATH with `openat(O_NOFOLLOW|O_DIRECTORY)` per component (each directory must be owned by the caller), writing a temp file and renaming it; the secret is never printed. `--rotate` replaces both copies the same way (old: `bad_credential`). The human reads `calls.log` with `sudo -u llmholder /usr/bin/python3 -I /opt/llmgateway/bin/keyholder.py log` (password required; no sudoers rule exists). Tests: the credential ends caller-owned and unreadable to `llmholder` and the reverse; a planted symlink is not followed.

**Authentication.** Callers `broker` and `service` read their credential file at start (restarts need no human step). A request carries `caller, ts, nonce, mac`, where `mac = HMAC-SHA256(secret, F(caller) F(ts) F(nonce) F(method) F(endpoint) F(path) F(run_id) F(sha256(body)))` and `F(x)` is a 4-byte big-endian length followed by the UTF-8 bytes (so no byte of a caller-chosen `run_id` can shift fields). Before authentication the holder caps frame size and applies a read timeout and a per-connection limit; it caches a nonce only after the MAC verifies, rejects a timestamp more than 30 s off (`stale_timestamp`: a WSL2 clock jump fails hosted calls loudly until time resyncs) and a repeated nonce; a retry signs a fresh nonce. It replies with a MAC over the response and request nonce; a caller first checks that the socket directory is owned by `holder_uid` (no fake holder). The holder appends `{ts, caller, run_id, endpoint, address, status, tokens}` (`address` = pinned address, per egress spec5) to `calls.log` per call (no bodies, no key).

**Request validation** (run ids are unauthenticated: a credential holder may name any, stated limit) (root config only, env ignored, the one `config.py` parser): an `https` `base_url`; the host resolved once, the address checked against forbidden ranges (loopback, private, link-local, metadata; unless `allow_private`) and connected to with SNI and hostname verification; no redirects; a response size bound (`max_response_bytes`, refused at start above 16 MiB = `ccg.broker.framing.MAX_RESPONSE_BYTES`); providers keyed by canonical origin (lowercase scheme/host, explicit default port; endpoints canonicalised before lookup; a collision stops the holder); `path` ∈ allowed paths; `body.model` an **exact member** of `pinned_models` (aliases and `-latest` fail, FR-9/AC-18); duplicate JSON keys rejected at any depth; the key read from `key_ref` on every call and kept out of logs, replies and errors (URL/base64 forms scrubbed, provider error text unlogged, core dumps off). The token limit and usage are read through this closed per-kind table, which the holder carries itself (it imports no adapter):

| Kind | Limit field (required, ≤ provider `max_tokens_ceiling`; the other kinds' aliases absent) | Usage fields (all settled) | Allowed body keys (closed) |
|---|---|---|---|
| `anthropic` | `max_tokens` | `usage.input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens` | `model, max_tokens, messages, system, temperature, top_p, top_k, stop_sequences, output_config, stream=false` |
| `openai_compat`, `lmstudio` | exactly one of `max_tokens`, `max_completion_tokens` | `usage.prompt_tokens`, `completion_tokens` | `model, messages`, the limit, `temperature, top_p, top_k, repeat_penalty, frequency_penalty, presence_penalty, seed, stop, response_format, stream=false` |
| `ollama` | `options.num_predict` | `prompt_eval_count`, `eval_count` | `model, messages, options, format, think, stream=false` |

An absent, over-ceiling or doubled limit is refused (`limit_missing`/`limit_over_ceiling`/`body_invalid`), never clamped (FR-18). A key outside the row, or `cache_control`/`tools` anywhere, is `body_invalid` unless the provider's owner config lists it in `extra_body_keys` (hosted `tools`/`thinking` need an entry).

**FR-10 ledger (hosted).** The holder owns `ledger.sqlite3`; `run_id` is MAC-covered. Owner config: `[[run_bounds]] match = "<glob>", max_tokens = N` (per run, no window); `unmatched = "refuse" | "cap"` (`cap`: one shared bucket of `default_bound` tokens per window); and the mandatory **window ceiling** `[holder] window_seconds, window_max_tokens, window_max_released` across all run ids (sliding, holder-wide only). The holder refuses to start with hosted providers and no ceiling, or with a value that is not a positive integer (`window_seconds` ≤ 30 days). In one SQLite transaction before sending it reserves `limit + len(serialized body)` (a byte-length bound on input), refusing if the run, `cap` or window total plus the reservation would exceed its bound (`run_id_missing`/`run_unmatched`/`run_bound_reached`/`window_ceiling_reached`). **Release by outcome:** a call that never wrote its request (validation, connect or TLS-handshake failure) and any complete HTTP error response (status ≥ 400) except 408/504/524 and a ≥ 500 whose body is not the provider's JSON error shape (edge-generated, possibly billed) release the whole reservation, at most `window_max_released` per window (beyond it: `release_cap_reached`, class `run_bound`); a complete 2xx settles to the reported usage (usage above the reservation is recorded as reported and the next call refused, per AC-6); a written request that never completed (timeout, abort), those excepted statuses, or a 2xx with unparseable usage, keeps its reservation until its window rolls off. So error-storm retries reserve nothing; the remaining lever (incomplete sent calls filling the ceiling or `cap`) rolls off and needs the credential. 

**Paths into the holder.** Broker: for an R7 allow its hosted `exchanger` signs a holder request and returns an `Exchange`; a new closed request field `gatewayRunId` carries the run id (spec5). Service: `HolderTransport`. A hosted call from a caller's own process fails `HostedFromCallerProcess` before any socket opens (AC-5, AC-7). `--require-owner-protected` is mandatory whenever the broker is given `--key-holder-socket` (it refuses to start otherwise).

**ccg path (FR-12, AC-21).** ccg interpreter → `Gateway` (ccg's process, `BrokerTransport`) → `BrokerClient.request` (component `answer.interpret`/`answer.summarize` from the call site) → broker policy and audit → R1: the broker exchanges with the local model; R7: the holder. U-S5 writes `docs/plans/connected-code-graph-egress-spec5.md`: spec3 §2.3 amended (credential held by the holder, forwarded hosted exchange, `gatewayRunId`, the refusal exchange), `server.py:main` flags and credential intake, the installed manifest (§3.6).

### 3.5 Configuration and owner trust (FR-2, FR-6, FR-20)
One file, `/etc/llmgateway/gateway.toml`, read by **one parser** (`config.py`) for library, service and holder; `LLMGATEWAY_CONFIG` overrides the path in the library only. **Owner configuration** passes `ownercheck.py`: opened `O_NOFOLLOW`, `fstat` and parse on the descriptor, owner uid ∈ injected `trusted_uids` (production `{0}`), mode `& 0o022 == 0`, every ancestor trusted-owned and not group/other-writable; re-checked every call. A failing file is **unprotected**: its `local_endpoints`, `scopes`, hosted steps, `scope_overrides` and `run_bounds` are ignored, hosted is disabled, and the local allow-list is loopback IP literals only. `is_local` compares a canonical origin (IP literal; userinfo and hostnames refused). Sections: `[deployment]` (`local_endpoints`, `holder_socket`, `holder_uid`, `state_dir`); `[holder]` (§3.4 ceilings, `unmatched`, `default_bound`, `ca_file`); `[providers.<id>]` (`kind`, `model`, `timeout_s`, `load`, `base_url` — the single URL source, FR-20/AC-14 —, `key_ref`, `pinned_models`, `max_tokens_ceiling`, `anthropic_version`, `out_of_credit_patterns`, `allow_private`, `extra_body_keys`); `[scopes.<id>]` (`marker = "restricted"|"unrestricted"`, `record_text`); `[scope_sources.<name>]` (`prefix`, §3.6); `[call_sites.<name>]` (`component`, `scopes`, `chain`, optional `local_chain`, `retry = {max, on}`, `settings`, `provider_settings.<id>`, `optional_settings`, `timeout_s`, `load_mode`, `load`, `bind_loaded`); a chain step is a provider id or `{provider, model?}` (model falling back to the provider table's); `timeout_s`: call site, else provider table, else default; `[[scope_overrides]]` is `{scope, chain, call_site?}`, tried in file order, the first whose scope is among the effective scopes (request-added included) supplying the chain, and a match without a list `chain` fails `config`; `[[run_bounds]]`. ccg's URLs exist once here (`interpret.py:LOCAL_ENDPOINT` is deleted); S18's startup check runs when ccg's `Gateway` is built and fails that start naming any call-site endpoint missing from the manifest's allow-list (one direction only).

### 3.6 Scopes, markers, and the ccg manifest (FR-3, AC-2, AC-21)
Scope ids are exact ASCII `[a-z0-9:._-]{1,128}`. A call site is bound to scopes in owner config; a request may only **add** scopes (unknown fields are refused, so none can carry a marker or remove a scope); a name not registered (statically, or under a recognised `[scope_sources]` prefix) is refused for any hosted step; a registered scope with no marker is `unrestricted`. Markers are read per call, per scope, uncached; unreadable or ill-typed → refuse. Resolution: precedence (overrides, then the call-site chain) picks the chain; a restricted scope with a hosted step from an override → refuse; from the call-site default → `local_chain` if configured, else refuse; hosted steps are never silently filtered. Text recording needs every bound scope `record_text` and none restricted.

**ccg mapping.** `[scope_sources.ccg-manifest] prefix = "ccg:"` makes every id under it source-backed: the loader rejects a static `marker` for any such id (the gateway holds no second copy of the local-only flag, AC-21). The ccg adapter derives `ccg:system:<system id>` (bound statically at the call site) and `ccg:repo:<normalized id>` per touched repository (added per request); the source answers `restricted` for a `local-only` repo, and for the system id when any repo is (stickiness). The broker's R5/R6 decision on the same manifest stays authoritative.

**Installed manifest.** The tracked `cpg/ccg/system.yaml` is agent-writable, so only the installed copy `/etc/llmgateway/ccg/system.yaml` (§3.4: `install.sh owner-files` byte-copies bytes read once, after human-confirmed diff, no ccg code) is read at run time, by the broker (`--system`) and the source. The broker carries its own owner-protection check (it must not import `llmgateway`; a parity test feeds both the same planted files) and loads once at start (D-4).

### 3.7 Call records (FR-5, AC-17, AC-19, AC-24)
`records.py`: SQLite in `state_dir`, one row per attempt (FR-5's fields: call id, attempt, component, scope, call site, run id, provider, reported model, hosted, fallback/retry reason, tokens, duration, outcome, failure class, loaded state, optional text); no header, error-body, request-id or org/workspace column exists. The store is advisory (the hosted ledger is the holder's); `RecordSink` keeps it replaceable.

### 3.8 Load and residency (FR-16, AC-13)
`load.py`: `Residency.loaded() -> [LoadedModel(id, context_length, raw)]` (`raw` = the provider's verbatim model record, from which ccg rebuilds `fingerprint` and `quantization`) and `load(model, settings)`. LM Studio `loaded()` reads `/api/v0/models` (`/api/v1/models` only when load settings are configured; ccg configures none). Ollama: `GET /api/ps`; load = `POST /api/chat` with empty `messages` and `options.num_ctx`. S10 wires the engine (after S6's hook): `on_demand` loads if absent; `explicit` is `Gateway.load(call_site)`, recorded; `strict` never loads (absent → `model_not_loaded`, nothing sent). A present model: no configured settings → accept and record; differing → fail naming the mismatch in every mode, never reload; equal → reuse. `loaded()` precedes any `load`; there is no unload. `load_mode` (call site, overridden by `Request.load_mode`) and `load = {context_length, …}` (call site, else provider table) drive this; a loaded context length differing from `load.context_length` fails `config` (never retried); `bind_loaded = true` binds the loaded chat model (the step's `model` is the preference), failing when none, never loading; ccg's are brokered. Ollama gaps (D-2): strict mode can race with load-on-call; idle expiry is not prevented (state recorded per call); thinking tokens count as reported; truncation is undetectable. 

### 3.9 Library-side bound
For runs matching a `run_bounds` entry the library checks `tokens_used(run_id)` over its own records before each call and refuses `run_bound_reached`: a cooperative early check (§3.4 holds the guarantee).

### 3.10 Seams for the follow-on and usage statistics
`RecordSink` and the `attempts` schema (stats adds no fields; hosted spend reads the holder ledger, as `attempts` is agent-editable); `provider_op` ops; `embed` refusal; `client.py` and the service protocol ; follow-on units go to `llm-gateway/docs/BACKLOG.md` (AC-10).

## 5. Test strategy

**5.1 Altitudes.** Unit: tables, policy, ownercheck, record guard. Integration: logging stand-ins (LM Studio, Ollama, Anthropic over self-signed HTTPS via `ca_file`, OpenAI-compatible) and real holder, service, broker subprocesses. Contract: ccg golden provenance, `client.py` hash. Live (`-m live`): LM Studio, Ollama; one human Anthropic smoke (thinking tokens, credit/spend-limit shapes).

**5.2 Verification by execution.** `trusted_uids` is injected: tests plant wrong-owner, group-writable, symlink, writable-ancestor and own-uid files (all refused).
- **FR-3 (AC-2, AC-4, AC-21).** Real broker (D9b) over a temp installed manifest, `ManifestMarkers`, logging stand-ins. (1) Local-only codebase + hosted override → refused, provider log empty. (2) Mixed system → every call reaches the local stand-in only. (3) Marker unreadable, then ill-typed → refused; flipped between two calls → the second differs (tightening). (4) Unregistered or confusable scope (`Workspace:acme`, trailing space, homoglyph), an unknown request field, a static `unrestricted` marker under `ccg:`, a `ccg:repo:` id over 128 characters → refused; adding unrestricted scopes cannot loosen a restricted one. (5) Unprotected config adding a hosted step → refused; one listing `https://remote` as local → refused, zero connections. (6) No hosted config + a remote OpenAI-compatible/Ollama URL → `HostedFromCallerProcess`, zero connections. (7) **Broker refuses independently:** the gateway source says unrestricted, the broker's manifest says local-only → R5/R6 deny, an audit `decision: deny` record, empty stand-in log (AC-21). (8) Editing the tracked `cpg/ccg/system.yaml` has no effect; a user-writable installed manifest, or `--key-holder-socket` without `--require-owner-protected`, stops the broker starting. Mutants: cached marker (3); no ancestor check (5); no R5/R6 (7).
- **FR-8 (AC-5).** Holder subprocess, fake key `sk-ant-FAKE-…`, stand-in HTTPS provider; hosted calls via service and broker. (1) Search the tree (untracked included), a scratch repo's `git log -p`, records, audit log, `calls.log`, logs, stdio, tracebacks, `/proc/<pid>/{environ,cmdline}`: no hit; a planted copy is found. (2) Mutant: the key logged on a 401 → fails. (3) Failing calls leak none. (4) Rotation and restarts keep authentication. (5) Direct holder calls: no/wrong credential, stale ts, replayed nonce, mismatched path/endpoint, a `run_id` with `|`, an oversized or slow pre-auth frame, unauthenticated floods (nonce cache does not grow) → refused or dropped; an injected clock jump → `stale_timestamp`; a retry signs a fresh nonce; a valid credential → served. (6) **Refusal table through the real broker:** each §3.3 code, from one ccg-shaped call, fails with its class, empty stand-in log, one attempt record, **no retry or fallback**; only a stopped holder yields `connection`. (7) Per kind a stand-in reply settles every usage field (cache tokens included); a body key outside the allow-list, `cache_control`, `tools`, and hosted Ollama without `num_predict` are refused. (8) A fake holder socket in an agent-writable directory → callers refuse. (9) `check-deployment` passes a correct layout and fails per planted wrong owner/mode (socket dir 0700; credential owned by `llmholder`; a code path or ancestor writable by a non-root uid, which also stops the holder; a planted symlink in the code root); `install.sh caller` follows no planted symlink. (9b) **Bootstrap:** with a planted `core.fsmonitor`, smudge filter, untracked `.pyc`/`.pth`, ignored file and modified `install.sh`, the extracted tree equals the committed tree byte for byte, no marker appears, and the unit command runs from it. (10) `Gateway(DirectTransport)` hosted → `HostedFromCallerProcess`. **Tier 2 (S20, `-m deploy`, real install):** the agent probe (same uid, shell, ptrace, `docker`) over the holder's files, `ps`, `/proc`, environment, a `/proc/<holder pid>/mem` read and a `ptrace` attach finds nothing, while it finds a planted same-exposure marker and succeeds on an own-uid process; it attempts to write the code root and its ancestors, and `sudo -n -u llmholder` of anything, and fails; `systemd-analyze verify` passes the unit; AC-5 needs tier 2.
- **FR-10 (AC-6).** Real holder, service, broker. (1) Bound N on `eval-*`: service and broker calls accumulate; the call whose reservation exceeds N is refused, nothing reaches the stand-in. (2) 8 concurrent calls near the bound → settled total ≤ N. (3) Missing run id, and a fresh id per call, sent straight to the broker and service sockets → refused (`refuse`) or one `cap` bucket. (4) 100 fresh `eval-N` ids stop at the window ceiling, which rolls off after `window_seconds` (injected clock). (5) The ledger survives a holder restart; deleting caller records changes nothing. (6) Release by outcome (§3.4): repeated 429s leave the window total unchanged until `window_max_released`; a 504, a hang, or 2xx with unparseable usage moves it and the `cap` bucket, recovering after `window_seconds`; invalid limits stop the holder; usage above the reservation is recorded and the next call refused. (7) Local calls without a run id are unaffected; the library check refuses a matching local run (advisory). Mutants: in-memory ledger (5); no reservation (2); no window (4).
