## Defects (harness owner)

**D1 (blocker; items 1, 2, 4-6, 8, 9).** `run` against a store whose default user has a password (`ccg-falkordb.sh --throwaway`, the lab's standard instance) exits 4, `bad input: AuthenticationError`, before any build or marker: `_default_deps.live_graph_present` and `snapshot_factory` (via `G.snapshot_graph`) open `FalkorDB(host, port)` with no credential. Repro: `ccg-falkordb.sh --throwaway up`; `gate_run.py run --gate-id ac5-gate-1 ... --port <it>`; a direct `G.snapshot_graph(...)` plus `StoreSnapshot(RoRunner(g)).snapshot_id()` raises the same. Fix direction: read-only role credentials for the reader and the live-graph probe (the harness already holds `ccg_verdict_<s>` / `ccg_raw_<s>`); the passwordless variant used here is unrestricted.

**D2 (blocker; items 2-10).** The build cannot start at the real `EVAL_COMMIT`: `_default_deps.refresh` passes `manifest=<clone at EVAL_COMMIT>/cpg/ccg/system.yaml`, absent at `cf7b2042` (added in `ffeac33f`). `run` exits 4 `FileNotFoundError` after the clone, leaving `gate-build-*`, `gate-work-*`, `gate-keys-*`, `gate-audit-*` and the lock file (a rerun cleans them). Repro: `git cat-file -e cf7b2042cce7bad5d0ab7876940bcea00343d914:cpg/ccg/system.yaml` fails. The held-out run uses the same `EVAL_COMMIT`. Fix direction: pass the manifest from the working tree (`repo`), not the clone. Also read from code, not run: the CLI's default `--system` is `ccg` while the manifest's system is `graphmind-ai-lab`, so `--system` must be given.

**D3 (blocker; items 2, 4; N4 half fixed).** The gate build passes a private `audit_dir` to `refresh` for verification, but the sandbox runner writes `sandbox.jsonl` to the default audit dir (`CCG_AUDIT_DIR` or `<ccg package>/../.audit`). F1 (exit 0): the default `.audit/sandbox.jsonl` grew by 38 records, the private `gate-audit-<key>/` stayed empty, all 10 python and 2 javascript units are `buildStatus: not-mapped` (941 Symbols, 0 ContractPoints), 49 of the 98 asked-item misses are `anchor-not-in-graph`. Offline check on the largest python bundle: `classify_bundle(records, <private audit>)` is `bundle:audit-missing`; against the default audit dir it is `None`. The run exits 0 with a silently half-built graph, and the developer's audit file is appended to. Repro: default environment, compare the default `.audit/sandbox.jsonl` size and `MATCH (u:Unit) RETURN u.language, u.buildStatus, count(*)` before and after. Fix direction: export the private audit dir to the sandbox writer, and fail the build when a code unit is `not-mapped`.

**D4 (major; item 6; the repeat-stall rule is unreachable).** The host-health canary calls `raw_query(CANARY_REQUEST, timeout_ms=30000)`; on the pinned instance (`TIMEOUT_MAX` 10000) the engine refuses it (`RawRefused`, "above the server's TIMEOUT_MAX"), so the canary always fails, the count never increments and a hanging engine holds the list in `failed:transient` forever, the case the ruling exists to prevent. Repro: `Client(system, host, port).raw_query("MATCH (s:Snapshot) RETURN s.snapshotId", timeout_ms=30000)` raises `RawRefused`; with 10000 it returns one row; F5 stops 1-3 leave `stall` empty. With `TIMEOUT_MAX` 60000 the same sequence converts on stop 3. Fix direction: clamp the deadline to the store's limit or fix the prereg field to a value the pinned store accepts; add a live test of the canary.

**D5 (major, design-open; item 3).** N5 realised on a key that is in the store: a gold http key containing `{?}` never resolves through the harness's consumer-form lookup (`unresolved`, 0 candidates), so the dry-run refuses (exit 5, `none`) and the cluster goes to dev. The built graph holds 14 `{?}` http contract points, so held-out anchors of this shape are plausible; dev has none. A `?query` gold key is not refused: its raw-key node is absent, so it is a counted miss without resolve. Decision for the owner and data-scientist: accept the shrink, or resolve these keys in provider form.

**D6 (minor; item 3).** A resolve refusal (exit 5) comes after a 16-21 minute build, leaves the live graph in the store, and the next fresh run on that store is refused (exit 2, "the store already holds the live graph"). The remedy (a new empty store, re-provisioned ACL users, a full rebuild) is not in either message.

**D7 (minor; item 9).** `score` on a list that never completed (marker `failed:transient` or `failed:deterministic`, no run file) exits 4 `bad input: FileNotFoundError`; with a run file present and the marker `started` it correctly exits 2 with the marker refusal. Expected: the marker refusal (exit 2) in both. No state changes.

**Observations (not defects):** a marker keeps the last `errorClass` after a later successful resume (`asked` with `errorClass` set); `asked` in the run summary counts distinct anchors (24, 39, 40, 44), not records; the answer count after a `SIGKILL` in ask k is k-1 (the in-flight ask is not recorded, as the rule intends).

## Setup errors (mine, not harness defects)

The lab's `requirepass` store (replaced by a passwordless one after D1); `l-xbad`'s planted bad symbol anchor never took effect (the asks are deduplicated by anchor and the cloned record sorts after the original), so F11 duplicated F10's asks; two script variable slips (`$S` unset in `20_scenarios.sh` f9 and `22_continue2.sh`) fixed and rerun; one compound shell command was blocked by the harness permission check for a reason I could not tie to its text and was rewritten as two script files.
