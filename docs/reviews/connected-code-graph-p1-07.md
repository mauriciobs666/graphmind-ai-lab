## Findings

### F1 (major) — the "only way an extractor decides these rules" Done-condition is enforced for argv alone, and the argv guard is a lexical tripwire
Verified (ran). `test_writer_rules.py:156-` `argv_field_writes` plus `test_only_writer_rules_writes_argv_fields_in_the_extractors` and `test_extractors_decide_the_rules_only_through_writer_rules`.
- **Obligations with no guard at all:** nothing flags an extractor that writes `bindValue`, `default`, `valueHash` or `defaultHash` itself, or imports `bundle._bind_grammar`, `bundle.name_fails`, `bundle._port` or `atrest.hmac_key`/`entry_hmac` directly. The name-grep covers only `bind_value_allowed`, `value_grammar_ok`, `gate_argv`. These matter most: the validator re-checks grammar/name rule/argv fixed point (`bundle.py:917-937`), but W2 (declared service), W3 alias anchor, and the `valueHash`/`defaultHash` domain are writer-only; a hand-written `{"bindValue": "acme:6379"}` or `valueHash = entry_hmac(key, keyPath, text)` passes the validator and the guard.
- **argv guard misses** (probed by calling `argv_field_writes`): variable or computed key (`K="args"; r[K]=a`, `{"com"+"mand": c}`, f-string key), `r.update(extra)`, `dict(zip(names, vals))`, `dict.fromkeys`, `dict([("command", c)])`, `{"type": "launchFact", **build()}`, `{"type": "decorator", "command": c}` (the typed-skip exemption is by a constant the author controls and the guard skips it, even in a writer that really emits a launchFact), `setattr`, a dataclass/namedtuple with these fields. Caught: `dict(command=...)`, `r["args"]=`, `r.update({"command":..})`, `r.update(command=...)`, `dict(**{"command":...})`, a non-constant `"type"`.
- **Does it matter for argv?** Little: the validator's fixed-point check (`bundle.py:927-935`) rejects an ungated argv at `write_bundle`. So the argv guard is defence in depth and its gaps are tolerable. It matters for the unguarded W2/W3/hash set above, which P1-10/11/12 will be written against.
- **Fix:** (a) extend the same AST walk to `bindValue`/`default`/`valueHash`/`defaultHash` key writes and to imports of `ccg.bundle` private names, `ccg.atrest`, `ccg.valuehash` from `extractors/**` outside `common/`; (b) replace the exemption-by-constant-type with an allow-list of record types the extractor writes through a small builder; (c) accept it is a tripwire and say so in the module docstring, naming the behavioural backstop per obligation (validator for argv/grammar/name; **round P1-11's behavioural test that a rendered fixture bundle's `bindValue`s all trace to `bind_fields`** for W2/W3). Per root `REVIEW.md`, add the guard extension in P1-11's row (the first writer), with its mutant (plant `{"bindValue": ...}` in a scratch extractor).

### F2 (minor) — `valueHash` text handling is not pinned (mutant n6 survived)
Verified. Mutating `value_hash` to hash `text.strip()` leaves 123 passed: no test hands whitespace-bearing text through `value_hash`/`config_entry_value_hash`. Spec §1.7.5 says the text is exactly "the value as the format's unescaping yields it". Add one row: a value with leading/trailing space and a trailing newline hashes to `_ref(KEY, rid, value)` unstripped.

### F3 (minor) — `O_NOFOLLOW` and the open-time `0o600` are not independently tested (m2, m5 survived)
Verified. Dropping `O_NOFOLLOW` (m2) and opening with `0o666` while keeping `fchmod` (m5) both pass 123. m2 is an equivalent mutant: `O_CREAT|O_EXCL` already refuses a symlink at the name, so the planted-symlink test passes without it; the flag is harmless redundancy, say so in the comment. m5 is the real gap: with `0o666` at open there is a window (umask-narrowed) where the file is wider than 0600 before `fchmod`; the plan's intent was that creation mode itself is 0600. Test by monkeypatching `os.open` to capture the `mode` argument (== `0o600`) and `flags`. Killed (verified): drop `O_EXCL` (m1), drop `fchmod` (m3), drop temp unlink (m4).

### F4 (minor) — stale temp files accumulate, but cannot break a later write
Verified by reading and the planted-name test. The temp name carries 64 random bits, so a leftover `.<name>.<hex>.tmp` never makes a later write of the same target fail (`O_EXCL` only refuses the exact random name; collision odds negligible), and concurrent writers no longer share a temp (an improvement over `<name>.tmp`). Cost: after a SIGKILL a 0600 hidden file lingers per crash, never reaped (the old fixed name was overwritten on retry). Not a problem for `*.jsonl` globs. Suggest a one-line note in `write_bundle`'s docstring; reaping is optional. Also unchanged and out of scope: no `fsync` before `os.replace`.

### F5 (minor) — `single_label_host` is public and fails open
Verified by probe. It returns `None` ("not single-label, no W2 needed") for any text outside `[a-z0-9-]+`, so a caller that passes an un-gated value gets "no restriction". Within `bind_value`/`launch_default` the grammar runs first and I confirmed uppercase, underscores, trailing dot, userinfo, `?`/`#` hosts all fail the grammar (so no W2 bypass today: 30 probes, none bound an undeclared single-label host). The dependency is implicit: W2 stays sound only while the grammar stays a subset of `[a-z0-9.-]` hosts. Drop it from `__all__` (underscore it) or have it raise on a non-grammar value.

### F6 (nit) — `entry_hmac` raises `UnicodeEncodeError` on a lone surrogate
Verified. `entry_hmac(k,"d","\ud800")` raises; a JSON `"\ud800"` unescape could produce such a text. Fail-closed and the spec is silent, so acceptable; the P1-11 writer should withhold-and-hash policy decide it (note for P1-11: catch and treat as unhashable per spec, not crash the extraction).

### F7 (nit) — coupling
`writer_rules` imports `bundle._port`, `_ipv6`, `_keypath_segments` (and calls `value_grammar_ok`, public). Acceptable inside one package; make them public if P1-14 also needs them, as the delegate says. `test_writer_rules.py` imports `rich_bundle` from `tests/test_bundle.py` inside `_records()` (lazy, so no collection cost); it works under rootdir-prepend (ran green in a scratch copy) and breaks only if `tests/` becomes a package. Acceptable; a shared `tests/fixtures` helper is the durable form.
