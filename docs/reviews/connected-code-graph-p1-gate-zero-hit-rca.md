## Symptom & impact

On a healthy built graph (all 1042 units `fresh`, under W3), `score` gives http 17/18 items, mcp 19/19, **scripts 0/46 items (0/21 anchors), wiring 0/11 (0/6 anchors)** (`gate-report.json` `recall.byStratum`; the report's 16/17, 20/20, 0/49 are other runs of the same list). Every one of the 58 misses is `no-qualifying-item`, stage `none`, `extractionAbsent` 0, `anchorNotInGraph` 0. `STRATA_GATED` includes both strata (`cpg/eval/tools/gate.py:56`; `-p1-gate-marker-ml.md` §4 item 3), so a real gate run would miss on every scripts and wiring item and spend the held-out list doing it (AC-5: a miss means a fix and a re-run on a **new** blind list, `docs/requirements/connected-code-graph.md` AC-5).

## Verdict on the four hypotheses

**(b) is the root cause, with (c) as the contributing factor. (a) and (d) are ruled out for the zero.** The engine/linker produces no item of the kind the gold names, because P1 builds no link from "script A runs script B by path" and no `config` item for a config entry that merely names a tool or server. The plan itself defers both to P2, yet gates both strata at P1.

## Reproduction & evidence

1. **Where each miss stops.** All 58 misses: stage `none` = no answer item passed H1 (`gate.py:560-589` `evaluate_item`: the stage is the deepest of H1-H3 any candidate reached). No candidate even matched the impacted element, so H2 (status), H3 (chain shape/replay) and H4 (group members) were never reached. A matching bug would show as stage H1/H2 near-misses; there are none.
2. **The answers are empty or off-target for these kinds** (join of dev gold to the answers by ask id, `run-db52…`): scripts: 45 symbol-anchored asks, all `resolved`, **0 items**; 4 contract-anchored asks (3 `GET /health`, 1 `send_message`) have items (confirmed Python callers, possible others) and **none is the gold shell `<script>`**. Wiring: the 4 symbol-anchored asks have 0 items; the 3 contract-anchored `send_message` asks return 20 items each, all `symbol`.
3. **Across all 311 answer lines of all nine runs, every item subject is type `symbol` (1703 of 1703); 0 `config`, 0 `unit`.** In the healthy run every chain is exactly ContractPoint, Link, CallSite, Symbol: 179 Link hops, 0 with `bound[]`, no `CALLS`/`CALLS_NAME` hop anywhere. The rehearsal report already notes "no `CALLS_NAME` hop in any answer". So on the real repo the engine lists only contract-mediated code consumers at P1; that is exactly the http/mcp shape.
4. **Harness is not at fault, run offline.** `gate._h1` called with a shell function subject (`skills/joern-cpg/scripts/test-stamp-wiring.sh::run_block`, line 168) against a fake snapshot returns True with no defects, so the H1 credit works for shell qnames. And it credits 36 of 37 http/mcp items on real answers. Config H1 (`stored_keypath`) was not exercised for want of a config item to feed it (rehearsal report: masked-key wiring not run); it is unreachable until the engine emits one.
5. **Anchor shape of the gold.** Scripts dev (49): 42 anchors are a script `<script>` symbol (23 with a `<script>` impacted, 19 other), 3 function anchors, and the chain is always one `caller` hop: *one script/module runs another by path*; 4 are http/mcp contracts with a shell consumer. Of the 22 shell-anchor impacted elements I could check, 21 are extracted as symbols (I ran `extract_shell` on them); in none does any call site name the anchor script (`callee-names-script` found 1 case, below) in a form that resolves. 17 impacted elements are Markdown prompt documents that tell an agent to run the script; 1 is Python. Wiring dev (11): config entries that (i) launch a script via a hook or agent (`opencode.json agent.tank`, 3), (ii) point a client at a server (`mcpServers.<x>`, `server.<x>` in TOML, Compose `services.server`, 4), (iii) name a tool in an allow-list or prompt string (`allowedTools[0]`, `tools[0]`, `prompt`, 3).
6. **Why the engine cannot link script to script.** Name resolution is `Name(lang, calleeName) -RESOLVES_TO-> Symbol(lang, name)` (`cpg/ccg/assemble/rows.py:482-484`, `by_name`). A script's symbol is named `<script>`; a command that runs it has `calleeName` `source`, `.`, `bash` or the path literal. They never meet; `CALLS` is written only for a same-file function (`cpg/extractors/shell/extract.py` docstring, "A name that is a function of the same file resolves to it; any other is `possible`/`name-match`"). The walk's `arg_name_out` row follows arguments *out* of a call, not into a script symbol (`cpg/ccg/engine/bfs.py:135-136`). The linker's only shell consumer pack is `shell-mcp-call` (`cpg/packs/shell-mcp-call/pack.yaml`): `mcp-call <tool>` only; no `curl` URL source, so a shell `GET /health` consumer yields no `CONSUMES` edge.
7. **Why no wiring `config` item.** `config` items are only `BOUND_BY ->` targets of a `Link` (`-answer-spec2.md` §3.3, V5): a config entry appears as *binding evidence for a code/prompt call site's link*. A kiro `allowedTools` entry or a TOML `server.x` stanza is not a call site's binding, and a hook entry that launches a script has no stored launch hop: `-p1-linking.md` P1-17 (6) "the script hop has no `BOUND_BY` entry because no extractor emits a shell script's `exec`/`docker run` launch fact"; `LAUNCHES` beyond `launchUnit` "is P2 (ruling)" (`-p1-linking.md` line 954). Fixture `BOUND_BY` works (10 on the fixture build, `docs/test-reports/connected-code-graph-p1-report.md:31`), so the mechanism exists; the dev gold simply is not that shape. *Inferred from the plan and the zero-`bound` answers; the real graph was not queried (the store is gone).*

## Causal chain

1. Gold for `scripts` and `wiring` was written to the **EP's** stratum definitions: §3.4 "every element that runs the script by its path", §3.5 config that "names, binds or launches" (`docs/plans/connected-code-graph-eval-protocol-ml.md`), consumer-first writers. Those definitions are broader than any P1 deliverable.
2. P1 builds: same-file shell calls, `mcp-call` consumers, URL/port-bound Links with `BOUND_BY` evidence. It explicitly defers shell launch/exec facts, shell URL sources, `-m` targets and the script hop (`-p1.md` line 518 P2 list; `-p1-linking.md` lines 563, 929, 954).
3. The gate plan nevertheless gates `scripts` and `wiring` (`-p1.md` P1-37 row, "scripts, wiring screened"; `STRATA_GATED`), and the gate-marker ruling and `-p1-ml.md` §6.1 quote a 159-item recall bound as if all strata were reachable. Nothing states an expected nonzero or zero for these two at P1.
4. So the engine, correctly per its own plan, returns nothing for them; the harness, correctly, reports 0.

**Ruled out.** (a) hit rule/matching: stage `none` for all 58, H1 verified on a shell subject, 36 http/mcp hits through the same code. (d) rehearsal setup: W1-W3 change auth, manifest and audit dir; D3 made 12 code units `not-mapped`, but the 0 reproduces with every unit `fresh` (report item 4), and the shell/config/markdown units were never affected by D3 (host extractors, no sandbox). Unit-anchor asks were answered through the single probe, not skipped: the "no answer" for the four unit-anchored wiring items is only my join key (answers are keyed by the probe's ask id), and the type census above covers them. One genuine but minor extraction defect (not the cause): `test-stamp-wiring.sh` fails tree-sitter parsing (`parse-error`, line 351, `bash -c '…'"$HERE"'…'` quoting), so the file keeps only `<script>` and loses `run_block`: the engine would also miss that item's gold even if linking existed (the report's `extractionAbsent` is 0 because it only tests the symbol's presence by `source_check_needed` on the extractor-visible spans; I did not trace that field).

## Root cause

**Confirmed (traced end to end, run artifacts plus source):** the P1 engine/linker has no path from a script-by-path invocation or from a tool-naming/server-pointing config entry to an answer item; 0 of 1703 answer items are non-`symbol` and the shell name-resolution cannot match `<script>`. **Inferred:** that the dev gold shapes, which the held-out lists will mirror because the same writers/definitions produced them, are the cause rather than an engine fault (read from plans, not from a graph query).

- **Trigger:** the first live run with real gold against the real graph (P1-32b rehearsal); fixture gates were green because fixtures plant the shapes P1 builds.
- **Contributing factors:** (i) EP §3.4/§3.5 defined the strata before P1's scope narrowed them to P2; no reconciliation row; (ii) `STRATA_GATED` and the recall bound assume all four strata reachable; (iii) no pre-gate probe: nothing in P1-41/P1-42 asks the engine a scripts- or wiring-shaped question on dev gold before the held-out run; (iv) the rehearsal reported the zero as "needs the engine owner" with no kind-level breakdown.

## Suggested fix and owner

A reviewer's suggestion is a finding for the owner to judge; none of this was run.

1. **Scope decision (stakeholder; stop here, not mine to take).** Either (A) *close the gap in P1*: new work for shell path-invocation links (extractor resolves `source`/`.`/`bash`/literal-path to a script symbol or the linker adds a `Link`-like edge; plus prompt-to-script mentions; plus config-names-tool and hook-launches-script items), which reopens P1-10/P1-11b/P1-17 and the answer spec (new schema/algorithm version, re-pinned goldens, a re-run of the pre-registered measurements); or (B) *narrow the gate*: AC-5 certifies `http` and `mcp` at P1, `scripts` and `wiring` reported "not delivered at P1, counted at P2", with AC-4/AC-2's scripts and wiring halves recorded as open. (B) changes AC wording and `STRATA_GATED`; (A) changes P1's scope. Running the held-out gate now is the one option that destroys evidence for nothing. Owner of the decision: stakeholder via `teco`/`tico` (requirements AC-2/AC-4/AC-5); consequences to `architect`.
2. **Whichever option:** `data-scientist` and `architect` reconcile EP §3.4/§3.5 and `-p1-ml.md` §6.1 with the chosen scope, so `minimumsMet` and the recall bound stop counting strata that cannot hit.
3. **Harness (`qa-engineer`, `cpg/eval/tools/gate.py`):** add a per-kind miss breakdown to the report (by derived stratum x anchor type x impacted type), so a zero names its shape; no change to H1-H4.
4. **Pre-gate guardrail (`qa-engineer`, P1-41/42 or a new check *before* the held-out run):** a dev-gold probe that asks every dev anchor shape and fails the pre-flight when a gated stratum has 0 dev hits unless the plan lists it as expected-zero. Put the assertion in a round before the gate step, not in P1-37 itself, so it can fail.
5. **Minor extraction defect (`coder`, `cpg/extractors/shell/extract.py`):** `test-stamp-wiring.sh` parse-error loses all function symbols; red test on that file first. Independent of the decision.
