## Findings

### Major

**M1 — Detector can lose connection records at the flush, so "zero `conn`" can pass with connections pending (inferred).**
`detector.pl:48-50,58` accepts at most one connection per ready listener per `drain`, each held up to 0.3 s (`:40`), serially; the flush path runs `drain(0)` only 5 times (≤15 accepts across 3 listeners), then writes `flush.marker`. `run.sh:`"signal_detector USR2" returns as soon as the marker exists, then the broker is stopped and `assertions.py` reads `conn.jsonl` within seconds, while the detector container is still up and still draining (128-deep backlog × 0.3 s ≈ 38 s). A buggy retry loop or hostile component that has ≥16 connections queued on ports 80/443/3128 at flush time leaves records that are unlogged when the verdict reads the file (after-flush records would fail the verdict, but only if logged in time; never-accepted ones are never logged). `window.py` cannot see this: it only judges what is in the file. The P-d probe-count (`len(probe.jsonl)==sent`) catches it only if the flood delayed the end probes.
Fix: at flush, loop `drain(0)` until no listener is readable AND the accept queue is empty (also read `/proc/net/tcp` `rx_queue` for the listening sockets, or `ss -ltn` Recv-Q, and write the residue into `flush.marker` as `pending:N`; `window.py` must fail on `pending != 0`); make the verdict wait for the detector's marker *after* the queue is verified empty; stop the detector (`docker stop -t`) and re-read before judging. Add a control in the detector-control scenario: 40 idle connections held across the flush must produce a FAIL, not a pass.

**M2 — Bridge "no address" check passes when `ip` fails (confirmed).**
`run.sh:net_up` (`/usr/bin/ip -j address show dev "$bridge" 2>/dev/null | "$PY" -I -c '…json.load…'`, then `[ -n "$(…)" ]`): any failure of `ip` (device not found, `ip` absent) or of the JSON parse yields empty output, which is read as "no address", i.e. the mechanism check passes. Reproduced: the same pipeline with a nonexistent `br-doesnotexist00` printed "passes for a nonexistent device". Concrete exposure: any Docker whose bridge is not in the harness's network namespace (Docker Desktop/remote `DOCKER_HOST`/rootless, or a different bridge-naming option) makes P-a's candidate-1 check silently vacuous; on a Docker that ignores the unknown `gateway_mode_ipv4` option the failure is caught only if the bridge is visible. The in-container probes (A1b/A1d) remain as the backstop, hence major, not blocker.
Fix: require `ip link show dev "$bridge"` to exit 0 and the JSON to contain exactly one interface with an `addr_info` key before accepting "empty"; otherwise `die` 70. Also refuse a non-empty `DOCKER_HOST`/`DOCKER_CONTEXT` that is not the local socket, and `unset DOCKER_HOST` explicitly beside the hard-coded `PATH`.

**M3 — INT/TERM/HUP run `cleanup` and then the script resumes (confirmed).**
`run.sh`: `trap cleanup EXIT INT TERM HUP`, and `cleanup` begins `trap - EXIT INT TERM HUP` and never calls `exit`. Bash runs a signal trap and then continues the interrupted flow. Reproduced with a 6-line stand-in: after `kill -TERM`, "cleanup ran", then the script went on to "step2 (created resource AFTER cleanup)", and exited 0. In `run.sh` that means a Ctrl-C or a `timeout`/teco kill removes the containers/network, then the run continues, `docker run`s new containers and networks with the traps already cleared, and may even return success. This defeats the header claim "removes only those … and verifies they are gone" and `test_ac8.sh` test 6 only exercises the `die` path.
Fix: separate `on_signal() { cleanup; exit 130; }` for INT/TERM/HUP, keep `trap cleanup EXIT` for the normal path, and make `cleanup` idempotent rather than clearing traps. Add test 6b: SIGTERM mid-run must leave exit ≠ 0 and no `ccg.ac8` resource.

**M4 — The probe token is learnable by anything in the component container; the only backstop is a count (inferred).**
`run.sh:probe_components` passes `token="$TOKEN"` as an argv word of `docker exec … perl /ac8/netprobe.pl`. Inside the component container that is `/proc/<pid>/cmdline` of a same-uid process, visible to any process in the container (same PID namespace) for the duration of each probe (start and end phases). A hostile or buggy component that learns it can send `AC8PROBE:<token>\n` to the detector at any later time; `detector.pl:44` files it in `probe.jsonl`, never `conn.jsonl`, so the verdict never sees it. What stops this today is `pre_d`'s equality `len(probe.jsonl) == Σ sent`. That is a weak invariant: it is global (not per component/phase/time), `sent` is taken from the component container's own stdout (a same-uid process can falsify it, e.g. by ptrace where the kernel permits), and the records are not checked for source address or timing. The token is also persisted in `docker-events.jsonl` (the `exec_start` action carries the command line) and shows in host `ps` for other users.
Fix (cheapest first): (1) give each probe invocation its own nonce, not the run-wide token, and make the detector accept each nonce once (single-use); (2) send the token on stdin (`docker exec -i … <<<`) rather than argv, and have `netprobe.pl` read it once; (3) in `assertions.py` require each `probe.jsonl` record to match exactly one expected `(component, phase)` by `srcAddr` (the harness knows every container IP) and by timestamp inside that probe's start/end interval, one record per detector target; (4) longer term, send the P-a positive control from a separate harness-owned probe container with a fixed `--ip` and let the detector classify by source IP instead of a shared secret. Also add to the detector-control scenario, run WITH a token file: tokenless and wrong-token connections must land in `conn.jsonl`, a correct one in `probe.jsonl` (today the control runs with no token, so the routing branch is untested by any live check).

**M5 — `--store-container` attaches a foreign container to the scenario network, making it an unobserved way out (inferred).**
`run.sh:main_run` does `docker network connect "$NET" "$STORE_NAME"` for a caller-named container, then relies on a `docker network disconnect` in cleanup. The store keeps its other networks (it is not created by the harness), so it is multi-homed with a route out. A component that speaks Redis to it can make it dial out (`REPLICAOF`, `MIGRATE`, a module loading remote data) and the detector, the strace and the in-container probes see none of it. spec3 §3.4 names "the broker's socket and the store" as the only ways out, so the store's own egress is exactly the gap. Also: nothing checks the name (`falkordb-dev` or `ccg-falkordb` would be accepted and have their networking changed; the header's "never touches another container" is false for this path), and `STORE_NAME` beginning with `-` is parsed as a flag by `docker network connect` (operator-supplied; low).
Fix: refuse a store that is not labelled `ccg.ac8.store=1` (or not named `ccg-ac8-store-*`), refuse the two known long-lived names, and after the connect verify `NetworkSettings.Networks` of the store has exactly the scenario network (otherwise `die`), or have the harness create the store itself with `--network "$NET"` only, `--cap-drop ALL`, and the Redis commands `REPLICAOF`/`SLAVEOF`/`MIGRATE`/`MODULE`/`CONFIG`/`DEBUG` renamed away. Use `docker network connect -- "$NET" "$STORE_NAME"`.

**M6 — What the zero-`conn` proof covers is narrower than the header says (design/coverage).**
`detector.pl` listens on TCP 80/443/3128 of one IP. With no default route, a direct attempt to an external IP fails locally (ENETUNREACH) and never reaches it; UDP, other ports and other scenario IPs are not logged. So `conn == 0` shows only that no component honoured the proxy variables; "no connection left" rests on the network mechanism plus the in-container probes (which a hostile same-uid process can falsify; theoretical). The `--workload` command runs as a host process with the host's full environment and network (`run.sh: env … bash -c "$WORKLOAD"`) and is outside the detector and outside the strace of the broker. `run.sh` header, "No traffic leaves the host … P-a is the acceptance test of that", reads as a measured guarantee.
Fix: reword the header and the report to the three things measured (isolated network + probes; broker strace; detector = proxy-honouring TCP only); consider running the workload under `strace -f -e trace=%network` or `unshare -n` with the broker socket mounted, and a host-side attempt counter (nft/conntrack counter on the scenario bridge) so an attempted-but-unroutable connection is visible. Record in the report that the "no attempt" claim is not made.

### Minor

- **m1 — P-e real resolver emits DNS from the host (answers lens e).** `pre_e` → `addr.default_resolver` = `socket.getaddrinfo(name, None)` (`cpg/ccg/broker/addr.py:85`): glibc nsswitch, search domains, mDNS/LLMNR, and the host's resolver, so a query for `<name>.invalid` leaves the host (a resolver that special-cases `.invalid`, e.g. systemd-resolved, may answer locally; unknown here). It runs after the window (the detector could not see it anyway), on every `run.sh verify`, and it runs for every non-local entry even when the `.invalid` suffix check has already failed (`assertions.py` `pre_e`: the failure is appended, the loop continues), so a real hostname in a manifest is looked up on the real network. Fix: only resolve entries whose host passed the `.invalid` check; make the stub resolver the default for `verify`, with `--real-resolver` opt-in; state in the header that P-e's real path is the one step that sends DNS. Severity is major if a manifest ever names a real host.
- **m2 — Row 8.16 trace scope and vacuity (lens d).** `strace -f -ttt -e trace=connect,sendto,sendmsg` omits `sendmmsg` (addressed datagrams) and `socket` (AF_PACKET/raw); use `-e trace=%network` and parse `sendmmsg`. The row passes with an empty trace: `trace_row` reports "N traced calls" but never requires `n_net ≥ number of allows` (each allow implies one traced `connect`), so a trace that captured nothing passes. Allows are matched as a set (`any((a,p)==key and t>=…)`), so one allow legitimises unlimited later connects to that address; make it one-to-one. Add `--seccomp-bpf` to `strace -f` (traces only the listed syscalls, otherwise every syscall stops the broker) to reduce observer effect; without it timeouts in the broker (connect/read, `wait_for 10 pgrep`) can behave differently from production. What ptrace needs: same-uid child tracing allowed by the kernel (Yama scope ≤1 is fine for a descendant) and a seccomp profile that permits `ptrace` (a harness run inside a container without `SYS_PTRACE` makes strace fail to start the broker: that dies 70, so it is fail-closed). `sa_family` unparsable lines are skipped silently in `parse_trace`; count them and fail on any in the window.
- **m3 — `cleanup` deletes by name without checking the label.** `docker rm -f "$c"` for names matching `ccg-ac8-"$ID"-*`; a pre-existing container of that exact name (stale or someone else's, e.g. after a scenario dir was removed but containers survived) is removed. Check `docker inspect -f '{{index .Config.Labels "ccg.ac8"}}'` equals `$ID` before `rm -f`. The network `case` pattern `ccg-ac8-"$ID"*` has no trailing dash (prefix-collides across ids) but only iterates this run's own list, so harmless today.
- **m4 — Scenario directory creation.** `mkdir -p "$BASE"; chmod 700` and `mkdir "$SCEN"; chmod 700` leave a umask window and follow a pre-existing symlink/attacker-owned `CCG_AC8_BASE`. Add `umask 077` at the top and `[ -O "$BASE" ] && [ ! -L "$BASE" ]`. Default path under `~/.local/state` is fine for a single-user host. The token file (`audit/detector/probe-token`, 0600 in a 0700 tree) is correctly placed and is never mounted into a component.
- **m5 — Operator-string handling.** `--components` is expanded unquoted (`for comp in ${COMPONENTS//,/ }`): globbing, spaces, and `../` reach `probes/$phase-$comp.txt` and container names. Validate `^[a-z0-9]+(,[a-z0-9]+)*$` like `--id`. `--store-port` is unvalidated. `--workload` is `bash -c` by design; document that it runs unconfined (M6).
- **m6 — A2 false pass if `getent` is missing.** `netprobe.pl` runs `exec('/usr/bin/getent'…) or exit 127`, and the check is `$rc != 0 && dt < 5`, so a missing `getent` reads as "DNS failed". Require exit status 2 (not found) and a positive `getent hosts <detector name>`-style control for the tool itself.
- **m7 — A1d accepts `EHOSTUNREACH`/`EADDRNOTAVAIL` as "unreachable".** An `EHOSTUNREACH` can be an ICMP from a router the packet reached. Local no-route is `ENETUNREACH`; accept only that for off-link host addresses and treat the others as failures to inspect.
- **m8 — Hardening is uneven.** The control component (`detector_control`) and the store stand-in lack `--security-opt no-new-privileges`, `--pids-limit`, `--memory`; add them as on the others. The broker env sets `HOME` but not `CCG_FORBID_REAL_CREDENTIALS=1`: nothing in the harness reads `~/.config/ccg` (grep of `cpg/ccg/broker` and the ac8 files shows no use), so set it as a backstop for the broker and `controls.py`. The probe argv carries the host's full address and listening-port inventory into every component container (`v4=… tcp=…`): harmless to isolation, but information a hostile component should not need; send it on stdin with the token (M4).

### Dispositions

- **M1 fixed.** `detector.pl` keeps a concurrent pending table; `drain` loops until `%pend` is empty, `queued()` (accept-queue `rx_queue` of state-0A rows of `/proc/net/tcp`, ports 80/443/3128; columns checked: `$f[3]` st, `$f[4]` tx:rx) is 0 and `$lsel->can_read(0)` is false, then writes `residue`; `window.py` fails on `flush-residue` and on a flush marker without it; the control scenario now floods `CONTROL_FLOOD=40` idle connections across the flush and expects residue 0; `stop_detector` stops (TERM drain) and verifies not-running before judging.
- **M2 fixed.** `lib.sh:bridge_has_address` returns "unknown" for a failed `ip`, bad JSON, empty list or missing `addr_info`, and `bridge_isolated_or_die` dies on unknown; non-local `DOCKER_HOST` and non-default context are refused (a rootless/Desktop daemon then also dies on the unknown bridge: fail-closed).
- **M3 fixed.** `lib.sh:ac8_install_traps`: INT/TERM/HUP `exit 130/143/129`, cleanup runs once on EXIT, signals ignored during it, cleanup label-checks before `rm -f`/`network rm`.
- **M4 fixed for points 1-3; point 4 deferred (acceptable, below).** Nonces are per (component, phase, target), 32-hex, single-use in the detector (`$used{$1}++`), carried on `docker exec -i` stdin (no argv, so neither `/proc/<pid>/cmdline` nor `docker events` carries a secret; the exec line is now `netprobe.pl broker=… ifaces=…`). `probe_attribution_problems` requires label, source IP = the component's container IP, each of the three ports exactly once, and the record time inside that probe's own `t0..t1` (+2 s). Analysis of the new protocol, as asked:
  - *Replay/ordering:* a replayed or earlier-used nonce is filed as a `conn` (control covers token-less, wrong, correct, replayed). A hostile process that steals a nonce (reading `/proc/<pid>/fd/0` or the probe's memory, same uid) can only use it before the probe does, in which case the probe's own connection becomes a `conn` and the verdict fails; after the probe it is a replay, also a `conn`. So theft yields a denial, not a hidden connection. Start-phase nonces are useless in the end phase (distinct).
  - *Source-IP spoofing:* a component cannot present another container's address without raw sockets/ARP forgery (`CAP_NET_RAW`); the stand-ins run `--cap-drop ALL`. Requirement for P1-40: real component containers must keep `--cap-drop ALL` (default Docker caps include `NET_RAW`). The IP check is a second factor on top of the nonce, not the only one.
  - *stdin protocol:* `key=value` lines, stdin wins over argv, skipped when stdin is a TTY; an empty stdin yields an empty nonce and the probe's own connection becomes a `conn` (fails safe). No injection path: the harness is the only writer.

### New findings

**N1 (minor-major) — The termination drain is not bounded consistently and its residue is never recorded.** `detector.pl` `DRAIN_MAX` is 30 s, but `run.sh:stop_detector` is `docker stop -t 20`, so a drain still running at 20 s is SIGKILLed, and the SIGTERM drain's residue is discarded in any case (`if ($want_term) { drain(); exit 0 }`; `stop_detector` checks only "not running", not the exit code). The flush marker's residue (clean) is already written before this, so connections made after the flush by a component that keeps connecting are lost silently instead of being logged as `after-flush` failures. They are outside the claimed window, but `window.py` names `conn-outside-window:after-flush` as a failure, and the loss is silent. Not exploitable inside the window (the flush drain and its residue are sound; a continuous flood or a stretched drain yields `residue > 0` and a FAIL: fail-safe denial, as asked). Fix: `docker stop -t 40`; write a `final.marker` (or a second field) with the TERM drain's residue and require it to be 0 in `window.py`; check the detector's exit status is 0.

**N2 (minor) — Coverage statements to carry into the P1-40 acceptance text.** (a) Held-open connections do not stretch the drain: every pending connection is logged at `t + HOLD` (0.3 s) regardless of whether the peer closed, so only new connections arriving continuously extend it, bounded by 30 s and surfacing as residue. (b) `queued()` reads only IPv4 `/proc/net/tcp` and the detector listens on IPv4 only (consistent; the network is IPv4-only by check), and a half-open SYN_RECV connection is not in `rx_queue` (the window for it is the microseconds before the final ACK; theoretical). (c) The `--workload` host process is still outside the detector and outside the strace of the broker; this is stated in neither the header nor the report (M6 asked for it). (d) Every cleanup/trap fix is verified by code reading; test 6 of `test_ac8.sh` was not run.
