## Findings

### M1 (major, verified): `[]`-valid vs attested is distinguishable only inside `build_rows`; no consumer path carries it
- `classify_bundle` returns `None` for a sandboxed and for a host bundle alike (by design). `attestation()` is called in exactly one place, `rows.py:444`, which fills `GraphRows.unattested_units`. Grep over `cpg/ccg`: `ccg/store/loader.py`/`swap.py` (P1-19, in flight) never read `unattested_units`; no `Unit`/`Snapshot` property carries it (spec6 forbids one); `auditSetHash` hashes ids only, so a host-only snapshot and a snapshot with no audits hash the same. P1-20's plan row lists refresh-report items (units fresh/stale-kept/not-mapped, wall time, peak memory) and not `unattested_units`. Spec6 §2's stated purpose, "an audit report never lists a host unit beside attested ones as if equal", therefore has no report to live in.
- Consequence: anything that reads the loaded graph or the refresh report sees host units as ordinary `fresh` units; "attested" is silently assumed.
- Fix (owner `architect`, then P1-19/P1-20 rows): add to P1-19's load report and P1-20's `RefreshReport` acceptance "carries `unattested_units` (ids) and the count, tested with one host `[]` unit and one host unit that names ids (both listed, a code unit not)", or state explicitly that the field is assembler-local until a later step.

### M2 (major, verified): spec6 contradicts itself after its own revision
`docs/plans/connected-code-graph-bundle-spec6.md`: (a) §1 S6a bullet still ends "the header-only `classify_bundle` does not", while two bullets later "`classify_bundle` ... also enforces S6a" (and the code does: `rows.py` `classify_bundle`); (b) the §2 `sandbox_audit.py` row still says `attestation` gives `host-unattested` "for the valid empty case, `sandboxed` for a valid non-empty one", while §1 says by language (code and tests do: `sandbox_audit.py:112-117`); (c) §2's `bundle.py` row lists only `HOST_LANGS` and `_s6a`, not the `rows.py` S6a. P1-44's coder reads §2 as the delta list; the stale rows describe the rejected design.
Related stale text: `tests/test_bundle.py` `test_classify_level_header_only_check_does_not_run_s6a` (docstring: "what `classify_bundle` sees ... passes"; it asserts only the schema, so it passes, but its name states the opposite of the shipped behaviour); `README.md` `ccg/assemble/` row says the assembler refuses on "the audit check, the version rule or the header schema" and does not mention S6a or `unattested_units`.
Fix: rewrite the three spec6 rows in place; rename the test to `..._the_schema_alone_does_not_run_s6a`; add one clause to the assemble README row.

### m1 (minor, verified): `attestation()` can raise, and returns `sandboxed` for a garbage `lang`, on headers that name valid ids
`check_sandbox_ids` never reads `unit` when ids are non-empty, then `attestation` does `header["unit"]["lang"]`. Probe (valid id present in `sandbox.jsonl`, `egressMode` offline): no `unit` -> `KeyError`; `unit: "x"` -> `TypeError`; `unit: {}` -> `KeyError`; `unit.lang: ["shell"]` -> **`sandboxed`**. Unreachable through `build_rows` (schema runs first in `classify_bundle`), but `attestation` is the public function P1-19/P1-20 will call, and spec6 §3(3)'s "does not raise" only covers the empty-list case (the test loops `[]` only).
Fix: in `attestation`, read the lang with the same `isinstance(header.get("unit"), Mapping)` guard `check_sandbox_ids` uses and return `invalid` unless `lang` is a `str` in the closed set; add the four probes above to `test_attestation_has_three_outcomes` with a non-empty id.

### m2 (minor, verified): rule S6a is implemented twice
`bundle.py` `_s6a` and the new loop in `rows.py` `classify_bundle` are separate expressions of one rule (differences: `r["lang"]` vs `r.get("lang")`, `by_type` vs a scan with an `isinstance` guard). Mutating either alone is caught (`s6a_dropped`, `classify_s6a_dropped`), but nothing ties their behaviour together, and a later amendment (say, S6a on `symbol.lang`) must be made twice.
Fix: one function in `bundle.py` (e.g. `s6a_violation(header, records) -> bool`) used by `_s6a` and by `classify_bundle`; a test feeding both the same crafted bundles.

### m3 (minor, verified): `build.py` still states the old rule (P1-44 follow-up, not a P1-44a defect)
`ccg/build.py:94,431`: "the schema requires one id (`minItems 1`)" is false for a host unit now, and `MissingAuditIds` (`:430`) still forces every host bundle to borrow code units' ids. Today that is harmless to correctness because `attestation` is by language (confirmed: `config` + ids -> `host-unattested`), but the message misleads and `HOST_KINDS` is a second host set (guarded by `test_build_host_kinds_equal_host_langs`; mutant `host_kinds_widened` is caught). P1-44's row must drop the host gate and the text; spec6 §1 already says so.

### n1 (nit): the schema `if` is vacuously true for a `unit` that is missing `lang` or not an object
Probe of the final schema: with `[]`, `unit` absent, `null`, `[]`, `{}` or lacking `lang` the `if` holds (or `else` fails) and the refusal comes from `required`/`type`, not from `minItems`; `lang` = `null`, `["shell"]`, `"SHELL"`, `"python"` all go to `else` and are refused by `minItems` **and** the `lang` enum. So the conditional is correct today only because `unit.required: [repoId, rootPath, lang]` and `lang`'s closed enum also refuse. Harmless; a comment in the schema `description` that the conditional leans on those two constraints would keep a later loosening honest.

### n2 (nit/question, owner `architect`): `-bundle-spec3.md` §2.2 row (line 959) still reads "at least 1"
Spec6 §2 row 1 says that row "becomes ... or `[]` when ...", but spec3 is superseded and (correctly) unedited; spec4 carries the `Extended by:` pointer to spec6. A reader of spec3 alone gets the old value. Acceptable if spec6 is the stated authority; say so in spec6 §2 row 1 or accept the gap.

## Direct answers to the brief

1. **The rule is exactly spec6's (final text).** `HOST_LANGS` is a tuple in `bundle.py` (`sandbox_audit.py` imports it; `bundle.py` imports no audit module: `test_host_langs_is_the_one_tuple_...`). Code languages with `[]`: refused by the schema alone (`test_the_schema_alone_refuses_...` over eight languages, via `bundle._validator()`, no S6a involved). S6a: empty list only, every file, equality, value-free message `line 1: header.sandboxAuditIds: S6a (...)` (regex-anchored in the test), in `bundle.validate` (so `loads`/`read_bundle`), and now also in `classify_bundle`. **Schema semantics (probed, final schema):** `if`/`else` without `then` is correct: `if` true -> no `minItems`; `if` false -> `minItems: 1`. Missing `unit` -> `if` false (`required: [unit]`) -> refused by `else` and by `required`. `unit.lang` null / array / `"SHELL"` / `"python"` -> `else` -> refused (`minItems` and enum), never a `TypeError`. Extra header or unit keys -> `additionalProperties`. See n1 for the vacuous case. `maxItems: 64` present; item pattern unchanged.
2. **S6a on real host bundles, independently.** The implementer's `test_host_bundle_s6a.py` passes (fixtures: 49 one-file plus 9 directory units, per its docstring). Independent run: `git archive HEAD` of `falkor-chat cypher-mcp mcp-monitor kiro opencode claude skills salesperson .mcp.json` into a scratch git repo, 612 per-file units (489 markdown, 82 shell, 41 config) plus 27 directory units (9 roots x 3 langs) through `ccg.build.build_unit`, each bundle re-read with `bundle.loads`, `sandboxAuditIds` emptied, `bundle.validate`: 1,835 file records (config 122, markdown 1,467, shell 246), pairs `(unit lang, file lang)` all equal, **0 violations, 0 build failures**. **Is the equality robust or a mirror?** It mirrors the extractors' own labels (`build.py:315` hardcodes `"config"`; the shell extractor uses `LANG`; markdown hardcodes `"markdown"`), and that is the intended coupling: the file `lang` vocabulary is the closed 11-value enum (`bundle-v1.schema.json:375`: no `json`/`yaml`), so a config extractor emitting a new file lang needs a schema enum change (a minor-version event) before S6a could even be reached; the failure mode is a loud `bundle:invalid` on a host bundle, which is the right direction. `test_host_bundle_s6a.py` is the tripwire. Not a finding.
3. **`attestation()` tri-state.** Final design: `invalid` if `check_sandbox_ids` errs, else `host-unattested` for any valid `HOST_LANGS` header (ids or not), else `sandboxed`. Pinned by `test_attestation_has_three_outcomes`; mutants `attestation_always_sandboxed` and `attestation_by_ids` both caught. A consumer **can** still treat a host bundle as sandbox-attested if it uses `classify_bundle`/`check_sandbox_ids` alone (both say "fine"); only `attestation()`/`GraphRows.unattested_units` tell them apart. See M1 (consumer paths) and m1 (robustness).
4. **Failure code.** `bundle:invalid` for a code unit with `[]` is consistent with spec6 §2 "failure code" and with `FAIL_REASONS` semantics (`-p1-graph.md` G4: `bundle:invalid` = header fails the schema; `bundle:audit-missing` = a named id without a valid record, or a host `[]`/ids with a non-offline mode). G4's wording is amended in the working tree (`git diff docs/plans/connected-code-graph-p1-graph.md`); `FAIL_REASONS` unchanged; no other file maps the code (grep: `staleness.py`, `rows.py` only). Accepted. One thing to watch for P1-20: a code unit that *loses* its ids now reports `bundle:invalid`, not `audit-missing`; its mapping must not special-case the old code.
5. **egress-spec3 §5.4.** Contrary to the brief, the sentence **is in the tree** (uncommitted working-tree edit, `docs/plans/connected-code-graph-egress-spec3.md:714`: empty list valid only for a host language with `offline`; `[]` means valid, never attested; `attestation` returns the three values; the assembly report lists `unattested_units`). Still to add, one clause: that `host-unattested` applies to **any valid host-language header, named ids included** (§5.4 currently reads as if only the empty list is unattested, the older design).
6. **Mutants (scratch copy `p144a_gate_cpg`, final tree, `-x` over the three test files; each turned a named test red):** `HOST_LANGS`+python (`test_host_langs_is_the_one_tuple_...`); drop markdown (same); schema `if` enum+python (`test_schema_if_enum_equals_host_langs`); S6a dropped, first-file-only, applied to non-empty lists, membership instead of equality (`test_s6a_*`, `test_rich_bundle_validates`); schema `else` `minItems` 1->0 (`test_header_schema[over5-False]`); `check_sandbox_ids` accepts `[]` for any lang and accepts host non-offline (`test_empty_audit_ids_pass_exactly_for_host_languages`); `attestation` always `sandboxed` / by ids (`test_attestation_has_three_outcomes`); `rows.py` unattested recording off (`test_a_host_bundle_with_no_ids_lands_...`); `classify_bundle` S6a dropped / first-only (`test_classify_bundle_*`); `maxItems` 64->6400 (`test_audit_ids_are_capped_at_64`); `HOST_KINDS`+java (`test_build_host_kinds_equal_host_langs`). Note: widening `HOST_LANGS` is caught by the literal-tuple pin (expected value written in the test, not read from the constant), so widening both the tuple and the schema enum together is still red.
7. **Stored bundles.** `bundle.read_bundle` (schema, S6a, all rules) on `tests/data/scip/real_ts.bundle.jsonl` and the nine `.ccg-work/vertical-slice/{dev,run1,run2,s14a,s14cf}` bundles, on the final schema: all ten OK (javascript, 3 ids, 2,771-2,775 records; python, 2 ids, 85,071 records, ~36 s each). Run in chunks under `ulimit -v 3000000`.

**Suites run (cwd `cpg/`, venv python):** `tests/test_bundle.py tests/test_assemble_rows.py tests/test_host_bundle_s6a.py`: 1,213 passed (the P1-19 `loader.py` test the brief said to ignore passed in this run too); `test_build_dispatch.py test_atrest.py test_config_extractor.py test_shell_extractor.py test_markdown_extractor.py test_joern_run.py`: 950 passed, 3 deselected (their own markers). ## What's solid
Conditional schema instead of a blanket `minItems: 0`, tested on its own; S6a checks every file, only the empty list, with a value-free message; exact-match `in` on a tuple, so no hashing and no case/Unicode folding; `check_sandbox_ids` still validates any named id and the egress mode for host `[]`; `unattested_units` sorted and kept out of `canonical_rows` (asserted); the `copy`/`minItems` pop hack in `rows.py` is gone and replaced by the real schema; every mutant in spec6 §3(5) has a pinning test with expected values written in the test.
