## Findings

### M1 (major, verified) — `flowdraw-p1` fails open when the exclusion file matches nothing

`load_exclusions` validates JSON shape only; `_is_excluded` needs `m["path"] == p` exactly. A custodian file with the wrong path form (`falkor-chat/server/x.py` instead of `x.py`, `./x.py`, a backslash) is non-empty and well-formed, matches nothing, and the tool draws the **unfiltered** first 30 and prints `0, 0`, the very outcome the non-empty check exists to prevent. The repo's own test shows it: `test_real_corpus_with_a_test_seed…` (`test_flow_p1.py:397-401`) passes `{"path": "no/such/file.py"}` and gets exit 0 and counts `0/0`. A hit would surface only at the later `freeze-check`. `defLine` is also unchecked (negative accepted, probed).
Fix: after loading, for **every** entry assert the file exists under `src_dir` and `1 <= defLine <= its line count`; abort with a fixed message (at most the entry's line number), writing nothing. This leaks nothing (it is the custodian's own input) and does not reveal which methods matched. Adapt the real-corpus test's dummy to a real corpus file with an out-of-span line, and plant a bad-path mutant. Not in the tool's spec today, so this needs a note line in §0.1 too.
