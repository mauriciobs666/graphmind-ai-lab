## Findings

### M1 (major) the per-field gate test reads its expected set from the table it checks, so a dropped source survives

`tests/test_indexed.py:127-136` parametrises over `_sources()`, which enumerates `indexed.BUNDLE_SOURCES`. Mutants (scratch copy `p118c_gate_tree`, 41 arguments-level mutants, see appendix): removing `("ConfigEntry","path","path")` from `launchFact` **survived** (458 passed), and so did removing it from `configEntry`. The import-time DDL check cannot see it either, because the sibling record type still maps the same `(label, prop)`. Consequence: a launch-fact or config path with edge whitespace is not refused at the gate (`bundle-v1` `path` pattern admits it), reaches `_Builder.node`, and raises `AssembleError` there, i.e. fails the **whole assembly**, which is exactly the blast radius P1-18b removes. The invariant test (`test_a_hostile_value_that_skips_the_gate…`, line 204) shows it is refused, not that the refusal is per unit.
**Fix:** pin the expected `(record type, field, label, property)` pairs as a literal list in the test (not derived from `BUNDLE_SOURCES`), one row per record type that builds a node: 15 rows today; and make the import-time check per record type, e.g. assert that every `b.node(label, {...})` property that `props_of(label)` lists is fed from a record type present in `BUNDLE_SOURCES` (AST over `_record`). Coverage probe, not a list: vary (record type that `_record` handles) x (indexed property of the label it builds) x (bad kind in `BAD`), and require `classify_bundle` to refuse each.

### M2 (major) the same blind spot for the header: `unit.repoId` has no test

Mutant `for (label, prop) in (HEADER_REPO, HEADER_SKIPPED_REPO): -> ()` **survived** (462 passed): no test plants a bad `unit.repoId`. I traced the sources: the bundle schema pins `repoId` to `[a-z0-9._-]` and the manifest normalises it (`ccg/manifest.py:87`), so I found no reachable hostile value today; the gate line is defence in depth with no test. Either add the plant (the schema refusal is then the first gate and the test documents it) or delete the dead branch.

### m1 (minor) `_clean` no longer stripping silently changes `Name.name` and loses `RESOLVES_TO`

Verified on the test world: a callsite with `calleeName = ' handler '` is accepted by the gate (`test_indexed.py:~150` says edge whitespace is fine there because the key is a hash that strips), but `Name.name` is now stored raw: `Name` rows `[' handler ', …]`, `RESOLVES_TO` **3 -> 2**, because `by_name` (rows.py:428) is keyed on the symbol's raw name. Before this change `_clean` stripped `Name.name`, so it matched. `' foo'` and `'foo'` also collapse to one `nameKey`, so which text the node holds depends on input order. Real data: 0 edge-whitespace callee names in 436,477 records (max `calleeName` 67 bytes), so this is a latent regression, not an observed one. **Fix:** either refuse edge whitespace in `calleeName` at the gate too (consistent with the ruling; the "hash strips" exemption is the only reason it is not), or build `Name.name` from the same normalisation `ids.name_key` applies and join `RESOLVES_TO` through it. Add a test with the padded callee and symbol of the same name.

### m2 (minor) a dropped Link can shrink a site's candidate set (inferred, not constructed)

`Link.key_norm` is the **provider's** key (`ccg/linker/link.py:20`), the consumer key is only a `VIA` edge property. A site with two candidate providers of different keys, one unindexable, loses that candidate's `Link` (`rows.py:650-653`), so `candidate_count` (`-p1-graph.md` §8 (d), count of `VIA` edges of equal `consumerKey`) falls from 2 to 1 and the site reads as unambiguous; only `dropped["cp-unindexable"]` records it. Likewise a dropped consumer fact leaves a `VIA` edge with no `CONSUMES` edge. I did not construct it; the live server load of the dropped case (`test_indexed_live.py:168`) shows no dangling edge (every created-count check passed), and `MOUNTED_BY`/`LIFTED_VIA`/`BOUND_BY`/`TO` edges are built inside the same loop iteration, so they go with the Link. Realistic only for non-`http` kinds with literal keys. **Fix:** when a Link is dropped for `cp-unindexable`, report it under its own count (`link-cp-unindexable`) so a reader of the report can tell a hidden candidate from a dropped fact, or drop every Link of that site/`consumerKey`.

## Questions asked, answered

**Predicate vs the engine facts (re-verified on v4.18.11 for P1-19b, and by the grid here).** Over `label (20) x edge char (6 ASCII whitespace + 5 Unicode non-trimmed) x position (start/end/both/only/interior) x byte length (4,094..4,098, 2/3/4-byte characters straddling 4,095/4,096/4,097)`: sound (no accepted value mis-indexed) and, with `over-flagged = {}`, exact: nothing the engine handles is refused. I added the one fact the grid takes from the implementer: an empty string is stored but `WHERE f.path = ''` returns **0** while a scan finds it (verified), so `EMPTY` is right. A lone surrogate in an *unindexed* property is `UnicodeEncodeError` at the client (verified), which no bundle can carry (m3). Mutants of the bound (`4095`, `4097`, `>=`), of each of the six characters (`\v`, `\f` dropped), of the Unicode over-flag (`\x1c`, NBSP added), of start-only/end-only, of bytes-vs-characters, of empty and of Unicode: all killed.
**DDL-derived list and the import check.** The list is parsed from `ddl_v1.cypher`; deleting a `BUNDLE_SOURCES` entry or an exemption fails the import (mutants for `File.path`, `Symbol.qname`/`nameNorm`, `Param`, `CallSite`, `Dependency`, `keyNorm` exemption: killed by `ImportError`). The check's limit is per `(label, prop)`, not per record type: that is M1. The exemptions (`Name.nameKey`, `Link.linkId`, `ContractPoint.cpId`) are hashes; `keyNorm` is gated where it is built.
**Uncovered sources, every label walked** (`rows.py` `build_rows`, `_record`, `_contracts`, `_mounts`, `_launches`): `Repo` (header `unit.repoId`; not-mapped units take the manifest's normalised `repoId`), `Unit` (hex32; not-mapped from `ids.unit_id`), `File`, `Symbol`, `Param/Ret/Cond`, `CallSite`, `Name` (hash), `Dependency`, `ConfigEntry` (both record types), `SkippedFile` (header `skippedFiles[].path`, appended directly, so it has no builder invariant), `ContractPoint` (three `_cp` call sites, all gated), `Link` (hash), `Pack`/`Snapshot` (unindexed). No uncovered source found; the two gaps are test gaps (M1, M2), and `SkippedFile` is covered only by the gate, with no invariant behind it.
**`_clean`.** Before: strings stripped. After: unaltered. Scan of the 10 stored bundles (436,477 records, my own scan with the shared predicate): **0** violations including empties, and no mapped field absent; edge whitespace occurs only in `constant`/`valueSet` literals, not stored on a node. So no stored value changes on real data, and the assembler slice equivalence holds (35 passed). The one behavioural change is m1.
**Dropped-CP semantics.** Symbols, call sites and handlers stay (test at `test_indexed.py:277`, and on the real server in the live file); no dangling edge; `dropped["cp-unindexable"]` counts the provider and the Link (2 in the test). Candidate-set effect: m2.
**Implementer's other findings.** Non-UTF-8 git path aborting a refresh: agree it belongs to P1-20 (the gate sees only decodable text); `test_real_git_paths_observed_through_refresh…` shows a trailing-space path stops at `bundle:invalid` and a 4,226-byte path at `extract:failed`, so the assembler gate is the third line, not the first. `ASSEMBLY_CODE` now including `ccg/indexed.py`, `ccg/store/__init__.py` and `ddl_v1.cypher`: acceptable. The DDL is a load contract that the predicate now reads, so a DDL edit (even a comment) changing `codeHash` and `snapshotId` costs one reassembly and swap, not an extraction; both removals were killed by the closure test.
