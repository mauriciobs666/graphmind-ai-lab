# Security review: P1-44a (host-bundle `sandboxAuditIds`, provenance lens)

> **Status:** active · **Owner:** `security-expert` · **Tracks:** C-1001 (P1-44a)

**Lens:** code/app, provenance (advisory). **Artifact:** the uncommitted P1-44a diff in `cpg/` (`ccg/bundle.py` `HOST_LANGS`/`_s6a`, `ccg/schemas/bundle-v1.schema.json`, `ccg/sandbox_audit.py` `attestation()`/`check_sandbox_ids`, `ccg/assemble/rows.py` `unattested_units`, `tests/test_host_bundle_s6a.py` and the bundle/assemble tests), read against `docs/plans/connected-code-graph-bundle-spec6.md`, `docs/reviews/connected-code-graph-bundle-spec6-security.md` (M1, m2) and egress-spec3 §5.3-§5.4. Root `REVIEW.md` read (no component `REVIEW.md` in `cpg/`). Probes ran on tiny synthetic headers/bundles in the scratchpad `sec-p144a/` with `cpg/.venv/bin/python -I`, `ulimit -v 1500000`, `timeout -s KILL 45`; no tree edits, no DB, no `~/.config/ccg`, no `cpg/.audit`.

**Verdict: approve with suggestions.** No blocker. M1 (loud distinct outcome) is closed at the function level and m2 (`file.lang == unit.lang`) is closed on the read path; two majors remain where the closure does not reach in practice (A: assembler does not enforce S6a itself; B: `attestation()` says `sandboxed` for a host unit that names ids).

CPG: considered, not relevant: the questions are a header constraint, a schema conditional and a label comparison, answered by reading the code and probing crafted headers; no input-to-sink flow through a CPG-indexed component was in question.

## Findings

### A (major, confirmed): S6a is enforced on the read path only; `classify_bundle`/`build_rows` accept a host-labelled `[]` bundle full of code-labelled files
`_s6a` runs in `bundle.validate` (so `read_bundle`/`loads`). `classify_bundle` (`rows.py:185-208`) validates the header only, and `build_rows` never calls `validate` or S6a (`grep S6a|bundle.validate rows.py`: no hits). Probe: took the test suite's `world()` host bundle (`config`, `sandboxAuditIds: []`), relabelled its `file` records `python`: `bundle.validate` refuses it with the S6a message, `classify_bundle` returns `None`, `build_rows` assembles it and lists it in `unattested_units`. So the m2 closure holds only if every `build_rows` caller obtained its records from `bundle.loads`. Today the only callers are tests; P1-20's refresh is where this becomes real, and the docstring ("Input is `bundle.read_bundle` output") is a convention, not a control. A third-party/stored bundle is still caught at `loads`, but any in-memory path (a cached parsed bundle, a future "rebuild from rows" shortcut) bypasses it.
Suggestion: make `classify_bundle` self-sufficient and cheap: when `h["sandboxAuditIds"] == []`, return `bundle:invalid` if any `records[1:]` item with `type == "file"` has `lang != h["unit"]["lang"]` (value-free, one pass, same rule as S6a; guard `isinstance(r, Mapping)`). Add a test using exactly this probe (relabelled files, `[]`) that fails without it. Also state in P1-20's plan that records reach the assembler only via `bundle.loads`.

### B (major, confirmed from code): `attestation()` returns `sandboxed` for a host-language bundle that names ids, and `build.py` still forces that today
`attestation` (`sandbox_audit.py:112-116`) keys on `header["sandboxAuditIds"]` truthiness, not on language. `ccg/build.py:381` writes `sandboxAuditIds: list(ctx.audit_ids)` and `build.py:430-431` *requires* non-empty `audit_ids` for every shell/config/markdown unit, so every host bundle the builder produces today names ids borrowed from the run's code units and is reported `sandboxed`, with `unattested_units == []`. Those ids prove a successful offline invocation exists somewhere (presence-only), not that this unit was produced by one; for a host unit it is provably false. Spec6 says "a host bundle that names ids stays valid" but never says it counts as attested; `test_attestation_has_three_outcomes` pins `shell` + ids -> `sandboxed`. Until P1-44 flips the builder to `[]`, M1's report line is empty in practice.
Suggestion: have `attestation` return `host-unattested` for any valid host-language header regardless of ids (the language, not the list, decides whether a sandbox could have produced it), keep `check_sandbox_ids` validating any named ids, and flip the pinned test. P1-44 must then drop the `MissingAuditIds` host gate (`build.py:430`) and its test; state that ordering in the P1-44 plan (P1-44a is delivered first, so no conflict, but the current `build.py` text still contradicts spec6 §1).

### m1 (minor, confirmed): second definition of the host set, no drift guard
`build.py:67` `HOST_KINDS = ("shell","config","markdown")` is the builder's own host-branch dispatch (`build.py:430,433,439`) and is the real control behind spec6's "the control is the builder". `HOST_LANGS` is "defined once" only for `bundle.py`/`sandbox_audit.py`; nothing compares `HOST_KINDS` to it (grep across `cpg/`: no test). Widening one without the other silently changes what the builder emits versus what the validator accepts.
Suggestion: `from ccg.bundle import HOST_LANGS as HOST_KINDS` (or assert equality in a test) in P1-44.

### m2 (minor): `unattested_units` has no consumer
It is a `GraphRows` field outside `canonical_rows`. `ccg/store/loader.py`/`swap.py` do not reference it, and P1-20's plan lists refresh report items without it. M1 asked that an audit report never list a host unit beside attested ones as equal; at present nothing prints it.
Suggestion: add to P1-20's acceptance: the refresh report carries `unattested_units` (ids) and the count, tested with one host `[]` unit.

### n1 (nit, theoretical): `sandboxAuditIds` has no `maxItems`
A 200,000-entry list of one valid UUID passes the schema (0.93 s) and `check_sandbox_ids` (0.10 s). Bundles are file-size-bounded elsewhere, so this is cost, not exposure. A `maxItems` (e.g. 64) is free.

## Direct answers to the brief
- **Code unit as host unit (label only):** a bundle `unit.lang = shell`, `[]`, with all `file.lang = shell` but real code inside passes every check, schema and S6a included, as spec6 itself states. Nothing on the tree can see it (a `shell`-labelled `evil.py` file id/path validates). Controls that actually exist: (1) the builder picks the host branch from `unit.language` and the file label from `units.classify_file` (extension/shebang) over the commit's bytes (`build.py:200-205`), never from a writer-supplied header; (2) host extractors parse only (confirmed in the spec6 security review), so a code file labelled shell by extension is parsed, not run, i.e. no sandbox-escape consequence; (3) `Unit` is built by `discover_units`. Inferred, not verified: stored bundles have no signature/MAC (`atrest.py` MACs keys, not bundles), so anyone able to write the work directory can author a `shell`-labelled bundle; that is the pre-existing at-rest trust boundary, now worth one sentence in spec6 §1 ("a bundle is trusted as far as the work directory is").
- **Bundle from something other than `build_unit`:** reaches `bundle.loads` -> S6a and schema apply (confirmed). Reaches `build_rows` without `loads` -> only the header-level `[]`/lang rule applies (finding A).
- **Consumers treating `[]`-valid as attested:** every reader in `cpg/ccg` is `rows.classify_bundle` (refusal path, correct), `rows.build_rows` (`audit_ids +=`, correct: contributes nothing; `attestation` for the report) and the tests. Loader/swap do not call either. No consumer misreads, but see B (the opposite error) and m2.
- **Message hygiene (confirmed):** S6a, schema and `check_sandbox_ids` messages contain no `lang` or `file` values. Planted `PLANTED-sk-LIVE-9999` as `unit.lang` and as a file path: neither appears in the `BundleError`; `classify_bundle` returns only a code (`bundle:invalid`).
- **Schema `if/else` with hostile headers (confirmed):** `Shell`, `SHELL`, `shell `, `shell\n`, Cyrillic `ѕhell`, fullwidth `ｓｈｅｌｌ`, `""`, `None`, `["shell"]`, `{"a":1}`, `1`: all fail the schema, `check_sandbox_ids` (error) and `attestation` (`invalid`), none raises. A missing/`None`/string/list/empty `unit` fails the schema (`required` plus the `else` branch's `minItems`) and yields `invalid`. `sandboxAuditIds` of `None`, `""`, `{}`, `0`, `[None]`, `[[]]`: schema fail, `invalid`. `egressMode` non-offline on a host `[]`: error, `invalid`.
- **`attestation()` fail-closed (confirmed):** missing audit dir: code header `invalid`, host `[]` header `host-unattested` (correct, no dir needed); `sandbox.jsonl` malformed lines (truncated JSON, arrays, `null`, invalid UTF-8, wrong-typed `auditId`): `invalid` with a count error, no raise; `sandbox.jsonl` a directory: `invalid`; header without the `sandboxAuditIds` key: `invalid`.

## What's solid
Closed enum plus exact-match `in` on a tuple (no hashing, no case/Unicode folding); conditional schema rather than blanket `minItems: 0`, schema tested on its own; S6a compares every file (not the first), is value-free and applies to `[]` only; `attestation` never raises and defaults to `invalid`; `unattested_units` sorted and kept out of `canonical_rows` (no graph property); the real-bundle test (`test_host_bundle_s6a.py`) builds actual host bundles through `build_unit` so S6a is checked against what the extractors truly emit.
