## Findings

### M1 (major) `create_users` resets and rotates live credentials before it knows it can store them

`ccg/store/acl.py:107-126`. The four `ACL SETUSER ... reset ...` calls run first; `atrest.write_acl` (which validates `CCG_CREDENTIALS_DIR`: not in the repo, 0700, etc.) runs last. On a rotation of a running system, a mistyped or repo-internal `CCG_CREDENTIALS_DIR` therefore resets all four live passwords, fails at the file write, then disables all four users (`_disable`), and leaves the old `.acl` file in place holding dead passwords. The unit test `test_the_credentials_dir_inside_the_repository_is_refused` (`tests/test_acl_unit.py:~150`) asserts exactly this sequence (4 resets then 4 `off resetpass`), so the behaviour is deliberate but it converts a config typo into an outage of a live system, when the check is free to do first. Verified by reading code and the passing test; not exercised live.
**Fix:** before the first `SETUSER`, call `atrest.credentials_dir()` (and the `_private_dir` check `write_acl` performs, e.g. a `check_credentials_dir()` helper in `atrest`) and raise `AclError` with zero server calls; keep the post-hoc disable for failures that cannot be predicted (disk full, server error mid-way). Test: same repo-internal dir, assert `admin.calls == []`.

### M2 (major, architect's call) the live grants are parsed at runtime from a `docs/plans/` file

`ccg/store/acl.py:36,43-62`. Good: no second copy, shape drift fails loudly, and the live matrix is an independent oracle for content drift. Against it: (a) a plan is a lifecycle document (root `AGENTS.md`: a gated plan gets a successor `…2.md`, an archived one stays put; an in-place revision for rework is allowed), so renaming or superseding `connected-code-graph-p1-graph.md` breaks `create_users` in production code, and an edit to §7's block silently changes shipped grants with no code diff; (b) the failure mode when the package runs from anywhere but a checkout is an `AclError`, acceptable, but it is the only runtime reader of `docs/plans/` in `cpg/ccg/`.
**Recommendation:** keep §7 as the *contract* in the plan, but move the four lines into a data file next to the code (`cpg/ccg/store/acl_users.txt`, same `ACL SETUSER` text), have `parse_acl_template` read that, and add one drift test asserting the plan's §7 block equals the data file (the live matrix stays the grant oracle). This keeps single-source-by-test and removes the runtime docs dependency. If the architect prefers the current design, record that §7 is code and must not be restructured, and pin it with a mutation test of the plan text (the current `test_a_changed_block_shape_fails_loudly` covers shape only).

### M3 (major, architect decides) the preflight extension is justified, but needs ratification and an upstream policy

`ccg/store/loader.py:85-97,289-301`. The plan's behaviour (4) requires only that a `nameKey` over 4,096 bytes not reach a constraint unhashed; the dispatch also refuses edge whitespace and >4,096 bytes for all 20 DDL-indexed properties. **Judgement: the check is correct and worth having as a backstop; it is outside the plan and should be ratified into P1-19's behaviours (and the loader row of the live spec at feature close), and an upstream rule is needed so it never fires on legitimate data.**

Engine facts, each re-verified on a fresh v4.18.11 throwaway:
- `CREATE INDEX`, then a `Name` with a 5,000-byte `nameKey`, then `GRAPH.CONSTRAINT CREATE … UNIQUE NODE Name PROPERTIES 1 nameKey`: the call returns `PENDING`, the server then dies (`docker inspect`: exited 139; log: `crashed by signal: 11`, `EnforceUniqueEntity+0x1e9`). The load-then-constrain order is not safe.
- Indexed equality: 4,096 `k` -> 1, 4,097 -> 0 (`STARTS WITH` finds it); 2,048 `é` (4,096 B) -> 1, 2,049 (4,098 B) -> 0. Bytes, not characters.
- Index trim: with `' x '`, `'\tx\n'`, `'x'` stored, `= 'x'` -> 3, `= ' x '` -> 0, `= '\tx\n'` -> 0; `U+00A0`, `U+2003`, `U+3000`, `U+0085`, `U+200B` edged values are found (1). I probed those five, not "every `isspace()` below U+3100" as the quirk entry says; I inherit that wider claim as unverified.

Real data (`cpg/.ccg-work/**/*.bundle.jsonl` + `tests/data/scip/`, 10 files, 436,477 records, schema 1.0, so a bound on the real corpora, not the full graph rows): **no string field over 4,096 bytes** (max `symbol.qname` 187 B, `callsite.targets[].qname` 187 B; the largest string anywhere is a 1,631-byte constant), and **no `path`, `qname`, `nameNorm` or `name` value edged with ASCII whitespace.** Edge whitespace occurs only in constant/`valueSet` literal values (`' '`, `'CONTEXT:\n'`, 400 hits), which are not indexed properties today.

Where a legitimate value can still reach the refusal: (1) `ContractPoint.keyNorm` is the pack's `key` (`ccg/assemble/rows.py:583`); for non-`http` kinds it comes from literals, which do carry edge whitespace in this corpus, and the `ids` hash strips but `keyNorm` itself is stored raw. I did not trace every pack's key derivation, so this is **inferred**. (2) `File.path`/`SkippedFile.path`: Linux/git permit a trailing space or `\r` in a file name (macOS `Icon\r`); and `SkippedFile.path` is itself indexed, so the row that is supposed to record an unusable file would be refused too. (3) A path over 4,096 bytes is not realistic (PATH_MAX); a `qname` or `keyNorm` over 4,096 bytes is possible for generated code or a long literal key.
**Recommendation:** keep the loader refusal as the fail-closed backstop (the alternative is a silently wrong answer or a server crash); add, owned by the assembler (P1-18, `ccg/assemble/rows.py`), a bounding step before rows are built: an offending `File`/`Symbol`/`keyNorm` is dropped or recorded with a reason code, and for `SkippedFile.path` a deterministic safe form (escape the six edge characters, or key it by hash) so one odd file name or literal cannot fail a whole system build. Without it, one `Icon\r` in a repo takes the system's refresh down for good. Coverage probe for that step, not a list: vary (label x indexed property from `ccg.store.INDEXED_PROPS`) x (edge character in the six x position start/end/both) x (byte length 4,095/4,096/4,097, ASCII and multibyte), and assert that no row reaches `L.load` with a refused shape.

### m1 (minor) rotation and fail-closed do not end open sessions

Verified: after a second `create_users`, connections authenticated with the old passwords kept working (`INFO` succeeded for all four; the old `engine` connection still ran `GRAPH.RO_QUERY` on live under the reset grants), and a user set `off resetpass` keeps its open connection (`CLIENT LIST` still lists it, `INFO` still answers). The module docstring says an authenticated connection stays up, so this is documented, but "rotation" and "fail closed" are weaker than they read: a leaked old credential keeps a session until it closes. The implementer did not test it. **Fix:** after a successful `SETUSER` (and in `_disable`) issue `CLIENT KILL USER <user>` from the admin connection, or state in the README row and docstring that rotation does not revoke sessions. A live test: open a connection, rotate, assert it is dead.

### m2 (minor) a test fixture still leaks plaintext under `--showlocals`

The redaction works for the default path: a planted failing run of `test_a_second_create_users_rotates_…` (mutated §7 giving the engine `+del`, `--tb=long`) and a planted failing matrix run (`raw` seeing build keys, `--tb=long -l --log-level=DEBUG`) printed **0** of the generated passwords and the admin password (stdout, `--basetemp` tree outside the `.acl` files, server log, `SLOWLOG` at threshold 0, `ACL LOG`: all clean; Redis redacts `SETUSER`). With `-l` on the rotation test, locals `first`/`second` (plain dicts from `read_credentials`) printed one password. **Fix:** wrap them in the existing `_Redacted` (`tests/test_acl_live.py`, the rotation test).

### m3 (minor) the matrix lets one over-grant survive; say so, or add a probe

Mutant `+unlink` added to the `(~ccg_<s>__build_* ~ccg_<s>__ov_* +del +expire)` selector survives (148 passed). Not harmful by itself (same reach as `DEL`), but §7 grants exactly `+del +expire`, and `BUILD_NO` has `UNLINK live` only. **Fix:** add `("UNLINK build key", _cmd("UNLINK", B1))` and the overlay key to `BUILD_NO`. The other survivors are equivalent and need no action: dropping `resetchannels` (`-@all` already denies every pub/sub command) and `+@all -@all` (a no-op) — both checked by reading the grant, not asserted by a probe; and the implementer's "only `+rename` on the verdict user" is **truly equivalent**: with it, `RENAME ccg_shop ccg_shop` succeeds (a no-op on the same key) and `live -> build`, `build -> live`, `live -> lock`, `lock -> live`, `lock -> lock` are all refused with "No permissions to access a key" (run on the throwaway, keyspace unchanged).

### m4 (minor) smaller points

- `_disable` swallows its own failure (`acl.py:84-89`), so `AclError` cannot say whether the users were actually disabled; add "(and disabling them also failed)" to the message when it did.
- Two concurrent `create_users` for one system are not serialised: users carry A's passwords and the file B's. Operator tool, low odds; one line in the docstring.
- The pinned image logs `Deprecation warning: Allowing a first arg of an otherwise blocked command is a misuse of ACL and may get disabled in the future (offender: +graph.config|get)` on every `SETUSER` of the build user (seen in the throwaway log). §7 and the loader's `TIMEOUT_MAX` read depend on that form. The image is pinned so it is safe today; record the warning and an upgrade trigger in `claude/graph-dba/falkordb-quirks.md` (the existing `+graph.config|get` entry, not the new one).
- `test_a_name_over_4096_bytes_hashes…` (AST) scans `rows.py` for the `"nameKey"` key of dict literals only; `dict(nameKey=…)`, `row["nameKey"] = …` or a second module would pass it. It is a bound; the loader bound is the real backstop, so leave it or widen it to the keyword/subscript axes.
- `README.md` row and the module docstrings are consistent with the code (no restated spec beyond the cell; fine).

## What's solid

- **Mutation results** (names `p119b_gate_*`, via `CCG_ACL_TEST_NOTE`, scratch copies of §7, the tracked note untouched), all killed: build without `+rename`; verdict without `+graph.query`, with `+rename`+`+del`/`+graph.ro_query`/build keys; engine with `+graph.query`/`+del`/without overlay; raw seeing build keys/with `+graph.query`; build with the flat `~ccg_<s>*`, full `~ccg_<s>` RW, `%RW` on live, `+expire`/`+del` in the root; selector without `+del`/`+expire`/overlay, widened to `~ccg_<s>*`, including live; lock selector without `+eval`/`+set` (build and verdict) or widened; `+graph.config` (SET) / `+graph.list` / `+graph.delete` / `+graph.profile`; without `+graph.config|get` / `+graph.constraint`. I mutated per grant axis, not each of the 150 probes individually: individual probe liveness is a bound.
- **Negative control and whitelist argument** pass and can fail: the flat `~ccg_shop*` user reads and writes `shop2`'s live graph while the real build user is refused on the same command and key; `shop__x` and `shop_` are refused by `check_system_name`/`create_users` with zero users and zero keys, and with the keys then planted by admin, `ccg_build_shop` reads `ccg_shop___build_1` (the pattern alone grants it), while the bare `ccg_shop_` is refused.
- **`create_users` mechanics:** one `ACL SETUSER <user> reset <tokens>` per role is atomic (verified: a bad token mid-line left the user byte-identical); `reset` drops a hand-added `>pw`, `~ccg_other*` and `+del` (live test); `token_urlsafe(32)`; `AclError` carries only user name and exception class (`__cause__`/`__context__` None, tested with an echoing fake); the file `<user> <password>\n` x4, 0600 in a 0700 dir through `atrest.write_acl`, read back through `atrest.read_acl` (compatible; `read_credentials` validates the four roles and the system).
- **Preflight tests:** before-any-call (`store.calls == []`), 4,096/4,097 boundary in bytes for ASCII and multibyte, all six edge characters x four shapes, NBSP/EM SPACE/IDEOGRAPHIC SPACE/ZWSP/NEL as loadable controls, lone-surrogate -> `LoadError`, the bounded set pinned to the DDL's 20 indexes, error text never echoes the value.
- **Fuzz:** the pure half (every `name_key` is 32 hex, NFC/NFD- and whitespace-edge-stable) and the live round trip (300 seeded strings + fixed shapes incl. a 100,000-byte name) hold; the loader interpolates only identifiers (`_ident`), values only as parameters, so "injection-shaped names delete nothing" can fail only on a regression to interpolation (still a useful tripwire). The quirks entry's three claims reproduce (see M3).
