## Findings

### B1 (blocker, verified) — `second_level_callee_only` counts argument-flow callee hops as call-depth-2 callees
`superset_dev.py:379-388`: `callee_hops` counts steps with edge `CALLS`/`CALLS_NAME` and `dir == "->"`. The record asks for items "listed only through a second-level callee hop (callee at call depth 2)" in V-both/V-union. But the shipped `arg_calls_out` row (`ccg/engine/bfs.py:135`, `CALLS ->`, state `path`) and its V-flow twin also emit `CALLS ->` hops, so a two-hop argument chain (the dev file has 4 `callee-arg,callee-arg` items) reads as "second-level callee".
Reproduced on `tests/test_engine_flow.py::reach_graph` plus `F2 -> F3` argument flow (probe in the scratchpad, `probe_second.py`): V-union item `F3` is reached by `DATA <-, CALLS ->, HAS_PARAM ->` twice (states `path`), `callee_hops` = 2, yet no V-both row is involved. V-both's genuine callee chain (`HAS_CALL ->`, `CALLS ->` into state `("end","callee")`) also gives 2.
Why it matters: the output would name items as second-level-callee-only that the V-flow rows list. Not used by the rule, but a must-emit diagnostic that is false cannot be corrected after the pin.
Fix (ran it on the same fixture): count only steps whose `tuple(s["state"]) == ("end", "callee")` as well as the edge test. Result: V-both F3 2, V-union F3 0, F2 1 in both. The test `_hop` (`test_superset_dev_tool.py:542`) builds hops with state `("end", None)`, so it encodes the wrong definition and must be rebuilt from a real walk; the assertion that would catch it: V-union `F3` over this fixture gives `None`, V-both `F3` gives a hit.

### M1 (major, verified by mutation) — plumbing that drives the pick and the emitted cuts is untested
In a scratch copy (see Appendix A) these 9 of 15 mutants survived the 95 tests: burden counted over dev-listed items only (M1: contradicts "all listed items, not only the dev items" and changes the rule's first key); the byte-equality check ignoring `chain`/`distance` (M2); port match without the `->` suffix, so port `1640` is accepted against a throwaway on `16400` (M3); set-union lower bound computed as an intersection (M4); `burdenMax` as `min` (M9); `unlistedPerWalk` printing the listed ids (M10); the cluster-level Wilson denominator changed from clusters to items (M11); second-level diagnostics emitted for V-flow too (M12); the as-built comparison's python cell reading the javascript cell (M13).
Cause: the only `measure` test over the real walk uses 3 items on one anchor where every returned item is a dev item (`test_superset_dev_tool.py:581`), and the Spy walk lists everything. No test has several anchors, several languages, a non-dev item in the walk, or candidates whose listed sets differ.
Fix: add, before the pin, a `measure` test over a hand-built multi-anchor graph (>= 2 anchors, python and javascript impacted files, a walk item that is not a dev item, candidates whose listed sets differ and whose union differs from the intersection), with expected values written down by hand (not read from `sd`). Then require a coverage probe over the axes the result varies on rather than a list: for every key of the emitted `candidates.*` / `setUnionLowerBound` / `asBuiltComparison` / `rule` block, a mutant that perturbs its computation must redden a test; run the sweep as part of the gate. Add the port-prefix case (`CCG_FALKORDB_PORT=1640` against `127.0.0.1:16400->`) to the non-throwaway parametrization.

### M2 (major, verified; record-level, fixable through the `-tool` line) — builder inputs the build imports or reads are unpinned
`pins.corpusAndBuilder.builderFiles` pins `cpg/ccg/**` (minus `engine/`), `cpg/extractors/joern/**` and two infra files. I imported the build path (`ccg.refresh`, `ccg.build`, `assemble`, `linker`, `packrt`, `store.*`, `engine.*`) in a scratch copy and diffed `sys.modules` against the 91 pinned paths: 14 imported files are unpinned: `ccg/engine/__init__.py`, `extractors/__init__.py`, `extractors/common/{__init__,errors,writer_rules}.py`, `extractors/config/{__init__,extract,formats,launch}.py`, `extractors/markdown/{__init__,extract,globs}.py`, `extractors/shell/{__init__,extract}.py`. The 7 `DEFAULT_PACKS` files `cpg/packs/*/pack.yaml` (plus the two `negatives.yaml`) are read by `build_and_load` and are also unpinned. They shape units, config entries and pack links, so graph content; whether they move the Symbol/CallSite walks of the 28 dev items is **inferred** (not measured). Phase B's digest only catches drift between A and B, not between the record and A.
Fix: the record cannot be edited, but the `-tool` line can carry them: extend `check_tool_line` to pin the two tool files plus these 14 + 9 files (or state in the line that they are outside the claim, with the reason). Decide before the line is written.

### m1 (minor, verified) — what the `-tool` line must pin: coherent, with two loose ends (item 7)
The record names only the live test (`tool.path`) and "the file's sha256"; the tool pins a two-key map (`TOOL_FILES`, module + live test, `check_tool_line` demands exactly those keys). That satisfies the record's refusal ("sha256 equal to the line's") provided the line states the map shape explicitly; say so in the line. Loose ends: the 95-test refusal proof `test_superset_dev_tool.py` is unpinned (the record calls it the tool's own test), and a one-line-per-id rule means a post-pin fix is a new id and a new tool constant. Decide whether the offline test is in the pin.

### m2 (minor, verified by reading) — `build_and_load` vs `refresh._run` (item 3): faithful for a full-scope build, four small divergences
Mirrored correctly: `discover_units` at `commit=`, `build_units` + `BuildContext(root=work, keys_root, manifest)`, `_resolve(..., work, audit, now)`, not-mapped list, `DEFAULT_PACKS`, `run_packs`, `Binder`, `link`, `build_rows`, `L.load(..., drop_stale=True)`; `all_units`/`carried_code_bundles` defaults are equivalent at full scope. Divergences:
- `links.bind_key_mismatch` is never read; refresh demotes such a unit to `stale-kept` (`refresh.py` ~507-514). Assert it is empty.
- the `one()` wrapper that turns `UnknownUnitKind` into a failed unit is omitted: a crash instead (acceptable, say so).
- the swap is a bare admin `rename` with no complete-build check (`:Snapshot` is written last, so `load` returning means complete); same as `tests/test_engine_flow_live.py`.
- host units are required `fresh` at EVAL_COMMIT but `Unit.flowAvailable` is not asserted false, although the record's premise is "all false, not overridden": add `r[9] is False` in `check_dev_ids`.

### m3 (minor, inferred from `atrest.py:62-110`) — add `CCG_FORBID_REAL_CREDENTIALS=1` in `use_scratch_dirs`
The tool points `CCG_CREDENTIALS_DIR`/`CCG_AUDIT_DIR` at the scratch dir and passes the same path as `keys_root`, so it is compatible with the test mode that raises if anything touches `~/.config/ccg`. Setting it turns the custody claim into a fail-closed guard. Not run. Also `test_the_real_phase` leaves `os.environ` changed (`use_scratch_dirs` writes it directly; the offline file has a restore fixture, the live file does not).

### m4 (minor, verified live on the fixture) — digest completeness is by enumeration
`graph_digest` enumerates `loader.ID_PROP` + `Snapshot` + `SkippedFile` and `EDGE_GROUPS`; `graphCounts` is derived from that dump, so a label or edge group outside it is silently absent (the missing `Snapshot` was exactly this). On my throwaway I ran `MATCH (n) RETURN count(n)` and `MATCH ()-[r]->() RETURN count(r)` as the engine role: 18 / 12, equal to the dump's counts, and the digest was identical for page sizes 1, 2, 3 and the default (keyset and `SKIP` paging live). Suggest running those two counts inside `graph_digest` and refusing on a difference; the live test only checks the counts against the loader's report on a 18-node fixture. The 10000-row split/refuse path is exercised only offline (monkeypatched `RESULTSET_SIZE`); a page of 4000 node rows and a 500-id edge chunk sit below the cap; not exercised live at scale.

## Checks on the numbered questions

1. **Contract fidelity.** Verified by reading and by re-deriving from the dev file: item match `kind == "symbol"` and `id == impactedId` (`listed`; `Item.kind` rules at `bfs.py:631`); anchor `("Symbol", anchorId)` accepted by `_check_request`; the walk gets only `column` and `table` (a test asserts the kwargs); table order irrelevant to the walk, `TIE_ORDER` = as-built, V-both, V-flow, V-union (49/53/62/66 as in the record); rule = max `s`, then burden sum, then max per-anchor burden, then the list (`rule_pick`, mutants M5 and the sum-before-max test redden it); burden = `len(Walk.items())` per anchor, summed (correct, untested: M1); set-union = V-flow ∪ V-both with the superset assertion; Wilson 28/28 0.8794, 4/4 0.5101; F4 comparison pooled 10/28, python 6/9, TS/JS 4/19 equals my recount (10 pure `return-use` chains; 6 python, 4 JS; 9 python / 19 JS impacted files). In-sample disclosure is a constant string in the result. Dev-data facts: 28 itemIds, 27 distinct impactedIds (two items on different anchors share one, handled item by item, fine). Except B1 and the M1 gaps, nothing leaves the tool a degree of freedom.
2. **Refusals.** Verified: `main` captures HEAD once (`capture_head`) and every record read is `git show <sha>:path`; `preflight` runs port, committed record, append-only, pins (dev, 7 engine files, registry, 3 plans, builder files, `test_engine_bfs_rows.py`), EVAL_COMMIT (equality to the pin and `cat-file -e`), dev counts, `-tool` line, `-snapshot` line (B) and the stage assertion, all before `phase_a`/`phase_b` and before any walk. Phase B compares digest, algorithm, snapshot id, unit commits, unit status, falkordb image digest before `check_dev_ids` and the walk. One planted input per refusal is in the 95 tests; the pinned-file parametrization flips one byte per group in both phases. Gap: the port refusal's prefix case (M1/M3).
3. **Delegates never run.** Static review only. Destructive steps are confined to the throwaway: the admin connection is opened on `ctx.port` that `check_port` proved is published by a `ccg-falkordb.throwaway=1` container (6379/6390 refused), `acl.create_users`/`LiveStore` only touch `ccg_*_flowfb` users and `ccg_flowfb__build_*` keys (`owned_build_key`), and `rename` onto `ccg_flowfb` overwrites only the throwaway's own live key. Credentials, HMAC key and audit go under `CCG_CONFIG_DIR/credentials|audit` (env set before the build; `atrest.credentials_dir` honours it over `~/.config/ccg/keys`, `default_audit_dir` over `.audit`). `image_ids` runs `build.sh --print-tag` (builds nothing) and `docker inspect` on `ccg-falkordb-tw-<port>` (the name the infra script gives). Re-running phase A on the same instance rotates the ACL passwords and replaces the live key, so phase B only matches if the build reproduces; phase A is not idempotent and should say so. Divergences from `refresh._run`: m2.
4. **G1.** Verified: `stage_unit` (`extractors/joern/run.py:155-215`) lists with `ls-tree -r` and reads blobs with `cat-file --batch` from the commit's tree, never `git archive`; units are discovered at EVAL_COMMIT (`discover_units(commit=)`); history comes from `git blame`/`log` at the commit with `blame.ignoreRevsFile` cleared and a shallow clone refused (`normalize/blame.py`). Completeness by enumeration: m4. Cap handling: m4. No timestamp is regenerated between phases because phase B re-reads the same live graph.
