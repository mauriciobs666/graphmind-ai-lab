> **Status:** active · **Owner:** `security-expert` · **Tracks:** C-1001 (P1-19b)

**Lens:** code/app security plus secrets custody (advisory; `devops`/`teco` decide). **Reviewed:** uncommitted `cpg/ccg/store/acl.py`, `cpg/ccg/atrest.py` (`write_acl`/`read_acl`, `write_private`, `read_private`), `cpg/ccg/sysname.py`, the preflight edit in `cpg/ccg/store/loader.py`, `cpg/tests/test_acl_unit.py`, `test_acl_live.py`, `test_fuzz_idhash_live.py`, against `docs/plans/connected-code-graph-p1-graph.md` §7 and §8 P1-19 (c).

Two majors: the §7 template is applied with no token allowlist (a tampered docs file escalates to full admin, reproduced), and the preflight refuses the whole system's build for one bad row.

CPG: considered, not relevant — the code under review is a new, uncommitted module with no loaded `cpg_*` graph that indexes `cpg/`; every path (template → `ACL SETUSER`, password → file) is short and was traced by reading and then exercised live.

**Method and safety record.** All server probing ran on one throwaway (`ccg-falkordb-tw-16391`, started by me via `infra/ccg-falkordb.sh --throwaway up` with `CCG_CONFIG_DIR` and `CCG_CREDENTIALS_DIR` on scratch dirs, `ulimit -v 3000000`, `timeout -s KILL`), removed by exact name afterwards. `falkordb-dev`, `ccg-falkordb`, `serene_gagarin` and the other throwaway present (`ccg-falkordb-tw-16390`, not mine; this is why my port was 16391) were never touched. `~/.config/ccg` mtimes were identical before and after. Probe scripts live in the session scratchpad, not the tree. All probes were against that throwaway (the tamper probe in M1 ran `FLUSHALL` there, within the brief's throwaway-only authorisation).

## Findings

### M1 (major, confirmed live): `parse_acl_template` has no token allowlist, so a tampered §7 block widens grants up to admin
`cpg/ccg/store/acl.py:52-58`. The only checks are: role/user shape, roles in order, `><secret>` exactly once, no other `<...>` placeholder, no `reset` token. Any other token passes, and `create_users` sends it verbatim after `reset`.
Evidence (copy of the docs file in scratch, `parse_acl_template(note)` then `create_users(admin, "shop", template=…)`): all five tampers were ACCEPTED, with no error: appending `~* +@all` to the engine line; adding `>evilpw` as a second password; `allkeys allcommands` on raw; `nopass`; an extra `~ccg_shop2` pattern. Live result for the `~* +@all` variant: the `ccg_engine_shop` user then ran `GRAPH.RO_QUERY ccg_shop2` (cross-system read), `FLUSHALL` (returned True, keyspace wiped), `KEYS *`, and `CONFIG GET requirepass` (returned the throwaway's admin password).
Why it matters: the single-source choice moves the security-critical grant from reviewed code to a prose plan that agents routinely edit; one stray token in `docs/plans/…-graph.md` becomes a live admin credential on the next `create_users` run, with the loud-failure net (`AclError`) not triggering. The existing mutation test (`test_a_changed_block_shape_fails_loudly`) covers role/secret/placeholder shape only; there is no tampered-grant test.
Suggestion: after parsing, validate every token against a closed grammar in code (not a copy of the grants): `on`, `><secret>`, `resetkeys`, `resetchannels`, `-@all`; `+<cmd>` or `+<cmd>|<sub>` with `cmd` in a fixed set of the 12 commands §7 uses; key tokens matching exactly `%W~ccg_<s>`, `~ccg_<s>`, `~ccg_<s>:verdict_lock`, `~ccg_<s>__*`, `~ccg_<s>__build_*`, `~ccg_<s>__ov_*`; selector parens only as the two §7 shapes. Reject `+@…`, `allkeys`, `allcommands`, `nopass`, `~*`, any second `>` token, any `~` not containing `ccg_<s>`. Optionally add a post-`SETUSER` `ACL GETUSER` readback compare. Add parametrized tamper tests using the five cases above (each must fail red today).

### M2 (major, confirmed offline; design call): the preflight refuses the whole system build for one bad row, so one hostile or accidental path blocks every refresh
`cpg/ccg/store/loader.py:~289-301`. The refusal fires before any store call (verified with a spy store: zero calls for a trailing-space path, a 4,097-byte path, a 5,001-byte `qname`, a trailing-tab `nameNorm`, a 6,000-byte `fileId`, a lone surrogate; the 4,096-byte boundary passes). That closes the crash and lookup-poisoning channels (below) but converts them into availability: a git-legal filename with a trailing space, or an over-long `qname`, in any one repository of a multi-repo system makes `load` raise for the entire snapshot. The prior live graph stays (fail-closed), but that system can no longer refresh until the repo changes.
Suggestion: have the assembler quarantine the offending row (e.g. a `SkippedFile` with a closed-set reason such as `path:unindexable`, or hash-encode the path) rather than raise at load; keep the loader refusal as the backstop. Decide whether a loud whole-build failure is the intended policy and say so in §4 if it is.

### m1 (minor, confirmed live): neither rotation nor the fail-closed `off resetpass` ends established connections
A connection authenticated with the old engine password kept working after a second `create_users` (`INFO` succeeded), while a new connection with the old password was refused. The docstring states the rotation half; the fail-closed half has the same property (`off` does not kill sessions; inferred from Redis semantics, same mechanism). Suggestion: after rotation and in `_disable`, issue `CLIENT KILL USER <user>` through the admin connection (best effort), and say so in the docstring.

### m2 (minor, partly inferred): `create_users` is not atomic across a crash or interrupt
(a) `_attempt` and the handler catch `Exception` only. I confirmed a `KeyboardInterrupt` raised inside `os.replace` propagates out of `create_users` (the temp file is cleaned by `write_private`'s `BaseException` handler); by reading `acl.py:110-126`, `_disable` is skipped, leaving four `on` users with fresh passwords nobody holds (inferred, not run). (b) A failed rotation disables a previously working user set and leaves the old, now invalid, `<system>.acl` in place (confirmed for the SETUSER-failure path: three users `off`, no file written). No leak, but a loud availability loss. (c) A `kill -9` between `_write_new` and `os.replace` leaves `.<system>.acl.<hex>.tmp` (0600, 0700 dir) holding the new valid passwords; `sweep_stale_tmp` covers only bundle temp names. Suggestion: widen the handler to `BaseException` (re-raise after `_disable`), and extend the stale-temp sweep, or document the residue.

### m3 (minor, confirmed): credentials-file hardlink is not refused
With `lnk.acl` hard-linked to another path (nlink 2), `read_credentials` accepted it; `_check_stat` checks owner and mode only. Same-uid attacker only, so low. The symlink case is solid: a symlink planted at the target made `write_acl` raise (`AtRestError`, users disabled, victim file intact), and after removing it the replacement was a regular 0600 file. Suggestion: refuse `st_nlink != 1` in `read_private`/`_check_chain` for key areas.

### m4 (minor): the build credential can steal or delete the verdict lock
§7 gives `ccg_build_<s>` `+set +get +del +eval` on `ccg_<s>:verdict_lock` (probe: build allowed SET/DEL/GET/EVAL there). The lock is what serialises verdict writers; the credential that runs repo-derived work can break it. Likely needed for the swap's guarded release (`RELEASE_LUA`), so this is a note for the design owner: confirm that build needs `+set`/`+del` rather than only the Lua release through `+eval`.

### n1 (nit): test locals hold real passwords
`world` is redacted well (planted failing runs with `--tb=long -l`, five failures including a `raise RuntimeError(world)`, a `GRAPH.DELETE` refusal and `assert conns == 1`: 0 hits for the admin password or any 43-char urlsafe token; the redis-py pool repr prints `password=<REDACTED>`). But `test_a_second_create_users_rotates…` and `test_acl_unit.py` keep passwords in plain locals (`first`, `second`, `creds_by_role`); `pytest -l` on a failure there would print them. Throwaway-only credentials, so nit. Suggestion: wrap in `_Redacted`.

### n2 (nit): `INFO` for all four roles shows `config_file`, `executable`, client counts
Required by falkordb-py's constructor and documented in §7; no secret in it (admin password not present). No action.

### n3 (nit): non-string values in an indexed property pass the preflight
`File.path` as int, float, list (including a list of 6,000-byte strings) or list with whitespace: not rejected by `_preflight` (it checks `isinstance(value, str)` only). Live on the throwaway: all stored, server stayed up, no crash; a string lookup is unaffected. A NUL string fails the build loudly at the engine, as the fuzz test says. Not a vector today; a one-line `isinstance(value, str)` requirement for indexed props would make the preflight total.

## Answers to the brief's questions

**(1) Passwords and custody.** `token_urlsafe(32)` gives 43 chars of `[A-Za-z0-9_-]`, safe as one whitespace-free token. No `subprocess`, `os.environ` or argv path in `acl.py`/`atrest.py` handles a password (grep), so nothing is `ps`-visible; the infra script uses `REDISCLI_AUTH` and a mounted config. Not in `MONITOR`, `SLOWLOG` or `ACL LOG` (captured live with `slowlog-log-slower-than 0`: no password from either password set; `ACL SETUSER` does not appear in MONITOR output). `AclError` carries user name plus exception class only; `__cause__`/`__context__` are None (live: a server-side error from an invalid `+nosuchcmd` gave `ACL SETUSER ccg_engine_fc failed (ResponseError)`). File: 0600 in a 0700 dir even under `umask 0` (observed 0o700/0o600), created `O_EXCL|O_NOFOLLOW` with `fchmod` before data, `fsync`, `os.replace`: no window with a wider mode, no partial file. `system` names `../x`, `a/b`, NUL, `A`, `x.acl`, `.x` were all refused by `check_system_name` before any server call or file. Rotation drops hand-added grants and passwords (`reset`, confirmed live in the committed live test's scenario and my own runs); old password refused for new connections. Fail closed: after a failure on the third user, the three created users were `off` with no passwords, and the unreached fourth did not exist; failing before the file write left no `fc.acl`. Gaps: m1, m2, m3.

**(2) Grammar and tampered §7:** see M1. Hostile `system` cannot enter the grammar (whitelist, ASCII only, `\A…\Z`); the risk is the docs-file source.

**(3) Confinement (probe on the throwaway; ~28 commands x 13 keys x 4 roles, plus script paths).** `shop` users reached nothing of `shop2`, `shop2__build_1`, `shop2:verdict_lock`, `shop_x` (zero permitted commands on every key). Build: `EXISTS ccg_shop` only on live (QUERY, RENAME-away, DEL, EXPIRE, EVAL-DEL refused); `DEL`/`EXPIRE` only on `__build_*`/`__ov_*`; `RENAME` any `ccg_shop__*` to live permitted (the documented residual); RENAME onto `ccg_shop2` or the lock refused; no `GRAPH.DELETE`, `GRAPH.LIST`, `GRAPH.COPY`, `FLUSHALL`, `KEYS`, `CONFIG`, `ACL`, `GRAPH.CONFIG SET` for anyone. Verdict: `GRAPH.QUERY` on live only, plus lock-key ops; cannot touch build/overlay keys, DEL, RENAME. Engine and raw: `RO_QUERY`/`EXPLAIN` on live and overlays only (no build keys, no lock). `EVAL`: allowed with zero keys (the selector has no key to check), but every `redis.call` inside is ACL-checked per call: GET/SET/DEL on live, shop2 and unrelated keys all "No permissions", `GRAPH.*`, `ACL`, `CONFIG`, nested `EVAL` blocked; only the lock key and (build) `DEL`/`RENAME` per the grant ran. World state unchanged after every script. `LOAD CSV` (file or http) by build and engine: errors for every path including `/etc/hostname`, so file read is not reachable in this image (the cause, e.g. an import-folder restriction, was not established; treat as unverified for other configs).

**(4) Preflight.** Called first in `load` (`loader.py:393`), before the first store call (spy store: zero calls on each refusal). The hash closes the id channel: every id/`nameKey` is a 32-hex `tuple_id` hash (`ccg/ids.py`) and the preflight additionally caps each id-property at 4,096 bytes. The residual hostile-name channels are the non-hashed indexed properties (`File.path`, `ConfigEntry.path`, `SkippedFile.path`, `Symbol.nameNorm`/`qname`, `ContractPoint.keyNorm`); each is covered because `_INDEXED_BY_LABEL` is read from the DDL (one list, no second copy), UTF-8 bytes (not chars) are measured, surrogates are refused, `" \t\n\v\f\r"` edges are refused and NBSP/`\x1c`/internal newlines correctly pass (engine does not trim them). Lookup poisoning reproduced live without the preflight: with `' x '` and `'x'` stored, `WHERE path = 'x'` returns both and `WHERE path = ' x '` returns none. The SIGSEGV (UNIQUE over a >5,000-byte value after data) was taken from the brief and the fuzz test, not re-run here; the unique-constrained properties are all id/`nameKey`/`unitId`, required non-empty strings and capped at 4,096 by the preflight. Remaining: M2, n3.

## What's solid
Single constructor for names/users (`sysname.py`, anchored `\A…\Z` regexes); `reset` first plus one atomic `SETUSER` per user (a failed one left the user nonexistent, not half-set); error text sanitisation; secrets never on a command line; `O_EXCL|O_NOFOLLOW` write with directory re-checks and fd-relative reads; per-field preflight driven by the DDL; the live matrix test design (planted `shop2`, `shop__x`, `shop_` keys, flat-pattern negative control).

2. M2: is whole-build refusal the intended policy for an unindexable row, or should the assembler quarantine it (`teco`/`architect`)?
3. m4: does `ccg_build_<s>` need `+set`/`+del` on the lock key, or only the Lua release via `+eval` (`architect`/`graph-dba`)?
4. `LOAD CSV file://` is refused here for an unestablished reason; `graph-dba` may want to confirm the import-folder setting rather than rely on it.

## Pass 2 (re-check of the fixes; throwaway `ccg-falkordb-tw-16390`, mine, removed by exact name; no other container touched; `~/.config/ccg` mtimes unchanged, contents not read)

**Verdict: approve with suggestions.** M1 is closed and I could not breach the ceiling; the remaining items are minor.

- **M1 fixed.** `validate_template` rejected all 64 smuggling cases I planted (0 accepted): the five original tampers; `+get|*`, `+eval|*`, `+get`, `+config`, `+graph.delete`, `+GRAPH.QUERY` case variant; `~ccg_<s>*`, `~ccg_<s>_*`, `%R~`/`%RW~*`/`%W~*`; `&*`, `allchannels`; `-@all +@read`, `+@read`; a selector with `~*` or `+@all`, a third selector, nested, unclosed, `()`, lone `(`, `)(~*` smuggled inside a token, mixed key sets; tokens after the selector; empty token, NUL, NBSP, fullwidth `+ｇｅｔ`, lookalike slash, newline or space inside a token, 500 KB token, 50,000 tokens; `reset`, `resetpass`, `clearselectors`, `on`/`off` repeats, `#`/`!` hash tokens, head reorder or missing `-@all`; cross-role commands and keys (raw `+rename`, verdict overlay key, build `~ccg_<s>`); a second `<secret>`; role order, extra or missing role, tuple and bytes tokens. Error text echoed no token. A subset of a role's ceiling is accepted by design. Why it holds: root tokens are exact-set matches against the role's ceiling, the head is compared verbatim, selectors need a non-empty key subset of one ceiling selector, and everything is ASCII-only. Verified (ran), not just read.
- **m1 fixed.** `CLIENT KILL USER` is effective: an engine session opened before a rotation raised `AuthenticationError` on its next command afterwards; the old password is refused for new connections.
- **m2 mostly fixed, one residual (minor, confirmed).** A single `KeyboardInterrupt` injected after each of SETUSER #1-#4, after CLIENT KILL #1 and #3, at `write_acl` entry, and inside `os.replace` on a rotation (old file present) always left a consistent state: every existing user `off` with 0 passwords, no credentials file, no temp. Residual: a **second** interrupt during the fail-closed path (injected on the `off resetpass` SETUSER) propagated and left `build` and `verdict` `on` with one password each. `_fail_closed`'s "never raises" claim is false because `_attempt` catches `Exception` only. Suggestion: catch `BaseException` per step inside `_fail_closed` and defer re-raising until every user was tried (or block SIGINT while it runs).
- **m3 fixed.** `read_acl` refused a hardlinked file; `nlink` is read from `fstat` of the opened fd, so there is no check-then-open race. Rotating with a hardlink to the old file present left the old inode with dead passwords and a new single-link file. `create_users` refuses an unusable directory (0755, inside the repo) with **zero** server calls and creates nothing in the tree.
- **Conftest guard: not bypassable by accident, but bypassable by design in several ways (minor).** Refused (ran against a fake `$HOME`, so the real directory was never an input): an explicit `keys_root`, a test setting `CCG_CREDENTIALS_DIR` itself, a symlink to the area, a changed `$HOME`, re-patching `_write_new` back to the original (another primitive still refuses), `prepare_acl_target`. Not covered: (a) `importlib.reload(atrest)` removes the wrappers and a write then succeeds; (b) a child process (`subprocess` with its own env) loads no conftest and wrote into the area; (c) `remove_acl`, `sweep_stale_acl_tmp` and reads (`read_acl`) are unguarded: against the fake area they deleted a file, swept a temp and read a file; the docstring says "no test may read or write". (d) an explicit `keys_root` is silently ignored while `CCG_CREDENTIALS_DIR` is set (env wins), so a test passing `keys_root` believes it isolates something it does not. Suggestions: guard `remove_acl`/`sweep_stale_acl_tmp`/`read_private` the same way, or route every area access through `credentials_dir` and put the guard there (one choke point); have `test_env_guard.py` pin a planted `reload` and an unguarded-primitive sweep; state that child processes need an explicit env.
- Offline `tests/test_acl_unit.py` and `tests/test_env_guard.py`: 96 passed (guard active, no mtime change under `~/.config/ccg`).
