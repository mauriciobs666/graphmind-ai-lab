## Findings

### F1 — blocker — JS `build_scopes` depends on fact order when two methods share a `fullName` (verified, executed)
`javascript.py:88-91` climbs a TYPE_DECL parent with `for m in methods.values(): if m["full"] == tpar["full"] and m["id"] in m2s: parent = ...; break`. This takes the first match in fact order. It is the JS twin of the Python defect the 5a gate fixed (F1: redefined class, same `fullName`). Probe: two `function f() { function inner() {} }` declarations (one `fullName`, two TYPE_DECLs), all 720 orders of 6 facts. Result: **2 distinct scope trees**, `a.ts::f.inner`/`f.inner#2` under `f` in some orders and under `f#2` (`f#2.inner`) in others. Either way both `inner`s hang under one `f`, which is wrong for the second.

The same-`fullName` shape is real JS: function redeclaration, and `if/else` branches that both declare `function f`. Symbol ids derive from qnames, so bundle bytes and `symbolId`s flip with Joern's emission order. That breaks spec3 §8.5 and the plan's determinism behaviour. The shuffle tests (`test_the_bundle_is_byte_identical_under_shuffles…`, `…redefined_class…`) are Python-only. The only JS order test is `…two_arrow_functions…whatever_the_fact_order`, and the slice `sp` bundle is compared in one order. The live two-run test would catch a Joern order change only on code that has this shape (not run, Docker).

**Fix:** resolve the owner the way `python.decorators_by_owner` does. Pick among same-`fullName` candidates by position (the nearest enclosing candidate at or before the child's line), with a total key `(l, c, id)`. Then add a JS shuffle test over all kinds, `m`, `t` and `p` on a redefined-function fixture, asserting identical scopes and **correct** parents. Do not hand over a list of shapes: run the permutation probe over every fact kind `build_scopes` reads (`f`, `m`, `t`) with a fixture that varies the two axes (shared `fullName` among methods; shared name among types).

### F2 — major — blame parser: an equivalence ruling is wrong and the abbreviated-block path is untested (verified, executed)
The delegate rules `blame.py:46` `i += 1`→`2` equivalent ("the lines in between are author fields"). It is not. For the 2nd and later lines of one commit, `--porcelain` emits an abbreviated block (header + `\t<line>`, no author lines). With `i += 2` the tab line is skipped, and the next header is swallowed by the inner loop. Probe on a 5-line single-commit file: real `{1,2,3,4,5}`, mutant `{1,2,4}`. The survivor is a test gap: the `history` fixture gives every line its own commit, so no test ever feeds the parser an abbreviated block. That is the dominant shape of real files, so only the slow slice test covers it.

**Fix:** add a direct `blame()` test with ≥3 consecutive lines of one commit (plus a second commit interleaved), asserting `per == {1:c1,2:c1,3:c1,…}`. The probe above is the red case. The other three blame survivors (`:47`, `:46`→0, `:69`) I confirm equivalent on reading.

### F4 — major — git invocation is neither hermetic nor literal-pathspec (verified, executed)
(a) `path_last_commit` (`blame.py:78`) passes the file path as a **pathspec** with no `--literal-pathspecs`. Probe: repo with empty `a.ts` and `z.ts` (changed later). `path_last_commit(repo, c2, "*.ts")` returns the commit of `z.ts`; `":(glob)?.ts"` likewise. A real empty file whose name carries glob/magic characters gets the history of other files. This diverges from the sibling convention `run.py:111` (`_git`: "Pathspecs are literal").
(b) Neither call isolates git from host configuration. Probe: `GIT_CONFIG_COUNT/KEY/VALUE` with `blame.ignoreRevsFile` makes `blame()` return a different commit for the same line. So `lastChangedCommit`/`lastChangedAt` depend on the host's or the source repo's git config (also `diff.algorithm`, textconv drivers), outside the §8.5 exemptions. The source repository is not trusted content.
(c) No `timeout=` on any `subprocess.run` here (blame on a hostile or huge history can hang the build), and `commit` is passed to `blame`/`log`/`rev-parse` with no `^[0-9a-f]{40}$` check, so an option-shaped value is parsed by git. A commit id from `raw.commit` is tool-made, so this is hardening.
**Fix:** one `_git()` helper for blame/log/rev-parse: `--literal-pathspecs`, `-c blame.ignoreRevsFile=`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_SYSTEM=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, a timeout, and a commit-id check at `build_bundle`. Tests: the `*.ts` probe and the ignore-revs probe as red cases.

### F5 — major — facts-supplied file names are not confined to the stage (verified at `Source`; flow read)
`Source.exists/text` (`core.py:76-85`) join `stage / rel` with `rel` taken from the raw facts. The facts come out of the sandboxed Joern run, which is hostile territory. Probe: `Source(stage).exists("../outside.py")` is True and `.text()` returns the outside file's content; an absolute `rel` is also accepted. `assemble` then does `(Path(stage)/f).read_bytes()` (`assemble_bundle.py:160`) and writes `contentHash`, `lineCount`, and the fingerprint of that host file into the bundle, an arbitrary-file hash oracle. `lang_files` filters by extension only. Not run end to end through `assemble`. **Fix:** reject, in `Source` (or `lang_files`), any `rel` that is absolute or whose resolved path leaves `stage` (a `BuildError`), with a test for `..` and an absolute name. Also decide non-UTF-8 files: `assemble_bundle.py:161` and `Source.text` decode strictly, so one Latin-1 `.ts` or Py2 `.py` aborts the whole unit with a bare `UnicodeDecodeError` (read, not executed). Spec3 says "decode as UTF-8" and names no handling. Ask `architect`/`teco` for the rule (skip-and-report vs `BuildError`) rather than let it stand by accident.

### F6 — minor — `assemble_bundle.py:292` is dead logic; rule on it
`ext = [o for o in ext if not o.startswith("__builtin")] or ext` is read only by `if ext and …` at `:293`. A filtered subset of `ext` is non-empty only if `ext` is, so the line changes nothing, while reading as if builtin targets were deprioritised. A dead filter is a finding: **delete it** (output is byte-identical; the slice equivalence confirms it). The earlier line (`ext` as a list) could then be an `any(...)`. The same applies to `javascript.py:186`'s `0 if "alias" not in x else 1` flag (the third key already orders `""` first; aliases are never empty), and to `python.py:156` `after or cands` (flagged dead in 5a P2-1, still there). I accept the delegate's ruling on `blame.py:47`/`:69`, `assemble_bundle.py:62`, `:104`, `:231`, `:287`, `:391` (read). `:257` `>`→`>=` is equivalent in practice, but if two `__init__` accessors ever tie on `dup`, the first in `scopes.values()` order wins; a `(dup, sid)` key would make it total.

### F7 — minor — pins not derivable from the spec, and one with no named owner
- The **lambda-as-decorator** record is the one pin that contradicts the spec's meaning: `run(lambda: 1)` becomes a `decorator` record `name="run"` on the lambda (`python.py:111-115`, `test_a_call_that_takes_a_lambda…`). Spec3 §5.12 defines `decorator` as Python/TS decorators on a function/method/type. This is the slice's 3-of-213 artifact kept for byte equivalence. The plan says later steps "pin their own named deltas" but names no unit that removes it. Ask `teco` to assign it (P1-09 or a backlog item) so it is not enshrined by default.
- Pinned observed shapes (read): `{"unknown":"point-derived"}` kept vs `{"unknown":…}` dropped, "first wins" for a repeated value-set path (`:372`) yet **last wins** for a repeated decorator-arg path (`:389`, `args[path] = [el]`), 3-fields vs 4-fields `data` truncation status, `ownedRegions` honoured for blame only. The first-wins/last-wins asymmetry has no spec source; both depend on the order of the inner `args` list, which no shuffle test permutes (shuffles permute fact lists, not `args`/`in`/`out`). Nothing in the plan hands these to a later unit; route to P1-09 (join/golden review) or document them as slice quirks.
- `ownedRegions` is read for `lastChanged*` only (`_blame_regions`); the symbol record never emits the field and `fingerprint` ignores it (spec3 §5.3 requires both when regions exist). Harmless for P1 (no frontend sets `s.owned`, and the plan says so), but the half-wired slot invites a later frontend to get blame right and the rest wrong. Note it at `core.py:97` or give it an owner (P2, per spec4 §2).

### F8 — minor — test and plumbing nits
`test_two_real_joern_runs…` ends with `assert out[0] != out[1] or raws[0].sandbox_audit_ids == raws[1].sandbox_audit_ids`, which has no failing case worth the name and should be dropped or turned into `!=` on the audit ids. `_HDR` hard-codes 40-hex, so a SHA-256 repo gives an empty `per_line`, and every symbol silently takes the fallback (visible only in `blameFallbackFiles`). `path_last_commit` indexes `out[0]` and raises `IndexError` for a path absent at the commit; `check=True` plus a clear `BuildError` is better. `locate_callees` can scan up to 400 lines per call with a lazy `<[^()]*?>`; bound it if hostile minified files are in scope.

### New findings
- **N1 — minor — only `GIT_CONFIG*` is stripped.** `_env()` keeps `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, which git honours over `-C repo` (inferred from git's documented behaviour; not executed). A build launched from a shell that exports one blames the wrong repository. Strip every `GIT_*` except what is needed, or allow-list.
- **N2 — minor — the 300 s timeout is per git call, not per build.** One call per file; a hostile repo with many slow files multiplies it. A build deadline would bound it.
- **N3 — nit.** `Source.text` of a missing file raises a bare `FileNotFoundError` (only `exists` is guarded by the caller), and `assemble`'s `raw(f)` safety rests on the `files` filter running first; a comment or a test that calls `raw` on a refused name directly would pin it.
